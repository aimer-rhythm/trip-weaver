## 1. 产品概述

### 1.1 一句话描述

一个开源的智能旅行助手：多 Agent 协作，从小红书真实笔记中调研目的地玩法，自动编排多日行程并落到地图上；注册即用、手机可用，行程可编辑、算预算、一键导出分享。

### 1.2 产品定位与运营形态

- **开源项目**（MIT 协议）：仓库公开，任何 IT 用户可按 README 一键自部署（Docker Compose）。
- **典型运营形态**：站长（IT 用户）在自己的 VPS 部署一个实例，通过**邀请码**分享给亲友圈使用。
- **主要终端用户是非 IT 人群**：从注册到生成第一份行程的必经路径上**不出现任何技术概念**（无 API Key、无 Base URL、无部署步骤）；主要使用场景是**手机 + 微信内置浏览器**。

### 1.3 核心价值主张

- **零门槛的 AI 行程规划**：注册即用，输入目的地和天数就出结果——技术复杂度全部留在站长侧。
- **攻略来自真实体验**：行程素材以小红书笔记为主要来源，玩法新鲜、避雷信息实在，每个活动可回溯到来源笔记。
- **多 Agent 分工保证质量**：调研、编排、审校各司其职，行程交付前经过预算与动线的机器审校。
- **生成过程透明**：三阶段进度与每次工具调用实时可见。
- **数据可带走**：历史行程存在站长服务器，随时导出 JSON / 长图 / PDF；长图为微信分享优化。

### 1.4 与工作区其他项目的关系

`D:\Project\luma-trip`（旅行摄影氛围指导应用）为独立产品，与本项目**无代码或数据关联**。

## 2. 目标用户与角色

| 角色 | 是谁 | 关键诉求 |
|---|---|---|
| **普通用户（主角）** | 站长的非 IT 亲友：自由行规划者、小红书重度用户、结伴出行组织者、预算敏感型旅行者 | 微信里点开链接→注册→生成→导出长图发群里，全程无技术概念 |
| **站长（运营者）** | 部署实例的 IT 用户（也是本项目的开源用户） | 一键部署；供 Key 成本可控（邀请码+配额）；小红书小号风险可控；出问题能自检 |
| **极客用户（少数）** | 想用自己 Key/自己模型的技术型用户 | 高级设置里 BYOK；不被强绑站点模型 |

**非目标用户**：需要真实预订能力的用户；多人实时协作团队。

## 3. 核心功能需求

### F1 智能行程规划（多 Agent 协作 + 小红书数据源）

**描述**：用户填写规划表单提交 → 前端经 HTTP API 创建生成任务（先校验当日配额）→ 后端三 Agent 流水线协作 → 进度经 SSE 实时推送 → 完成后行程入库并展示。

**输入表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 目的地 | 文本 | ✅ | 城市或地区 |
| 天数 | 数字 1–15 | ✅ | 行程天数 |
| 出发日期 | 日期 | ❌ | 影响展示与导出 |
| 预算档次 | 经济 / 舒适 / 豪华 | ✅ | 引导消费水平 |
| 总预算金额 | 数字（元） | ❌ | 启用超支预警与审校规则 |
| 旅行偏好 | 多选：美食/文化/自然/购物/亲子/夜生活/小众 | ❌ | 影响调研关键词与选型 |
| 出行人数 | 数字 | ✅ | 费用按全团估算 |
| 补充要求 | 自由文本 | ❌ | 如「不吃辣」「带老人节奏慢」 |

**多 Agent 流水线**（拆解见架构 §5）：

| 阶段 | Agent | 职责 | 主要数据来源 |
|---|---|---|---|
| ① 调研 | 目的地调研 Agent | 搜索小红书笔记，提取候选 POI（玩法/口碑/费用线索/避雷/来源链接） | **小红书（主）**，模型知识（兜底） |
| ② 编排 | 行程编排 Agent | 从候选池选点、查真实坐标、按天编排（时段/描述/费用/类别） | 候选池 + OSM 地理编码 |
| ③ 审校 | 行程审校 Agent | 预算符合度与动线合理性审查，不通过打回修订（≤2 轮） | 行程草稿 + 预算聚合 |

**行程质量要求**：每天 4–6 个活动，含时段/简介/费用（人民币全团口径）/类别；坐标优先真实地理编码，失败才用估算坐标并标记；小红书来源活动附来源笔记链接（≤3 条）；小红书不可用时自动降级为模型知识规划并标注。

**生成过程 UX**：三阶段进度 + 工具调用时间线；随时可取消；可离开页面回来恢复订阅；完成后显示本次 token 消耗；草稿隔离——失败/取消不产生残缺行程。

**异常与降级**：

| 场景 | 行为 |
|---|---|
| 当日配额用尽 | 提示「今日 N 次生成已用完，明天再来」+ 显示重置时间（见 F8） |
| 站点未配 Key 且用户未 BYOK | 提示联系站长（普通用户）/ 前往高级设置（极客）+「加载示例行程」 |
| BYOK Key 无效（401/403） | 明确提示检查高级设置 |
| 小红书 MCP 不可达 / 登录失效 / 全站日额度用尽 | 自动降级为模型知识调研，行程标注「未使用小红书数据」 |
| 地理编码失败 | 单点降级：估算坐标 + 标记 |
| 审校 2 轮仍不通过 | 以当前最优草稿交付 + 审校遗留问题清单 |
| Agent 循环异常中断 | 报错；不产生行程记录（不计入配额） |

**验收标准**：

- [ ] 普通用户（未配任何 Key）注册后直接生成「上海 3 天 2 人 舒适」成功；≥60% 活动带来源笔记链接。
- [ ] 三阶段进度与工具调用时间线实时可见；取消无残留；刷新页面可恢复进度。
- [ ] 关闭小红书 MCP 再生成：流程不失败，行程带降级标注。
- [ ] 90%+ 活动坐标来自地理编码（知名城市），地图无飞点。
- [ ] 配额用尽后创建任务被拒且文案正确；失败任务不扣配额。

### F2 地图可视化

- 活动序号标记（当日顺序号，8 天色循环）+ 每日同色折线 + Popup（活动信息/来源笔记链接/编辑入口）。
- 天数过滤器（全部/D1/D2/…）同时作用于地图与清单；变化时自动 fitBounds。
- 坏坐标不上图（清单标「无坐标」）；估算坐标虚线样式。

**验收**：3 天 3 色 3 线；D2 过滤自动缩放；改坐标标记即动；**微信内置浏览器与手机端正常渲染**。

### F3 预算计算

- 活动费用可随时编辑；自动聚合总费用/按天/按类别（日小计入每日区块头部）。
- 设总预算后显示 vs 进度条，超支红色 + 差额；纯 CSS 条形图。

**验收**：改费用三处联动；预算 1000 费用 3000 出现正确超支提示。

### F4 行程编辑

- 活动级：增/改（全字段）/删/日内上下移/移动到其他天；天级：增/删（确认）/改主题；行程级：改元信息、重命名。
- 编辑防抖自动保存到服务端，保存状态可见；多端以服务端为准。

**验收**：全链路可用；换浏览器登录改动可见；删除类操作有确认。

### F5 导出功能

| 格式 | 内容 | 用途 |
|---|---|---|
| 长图 PNG | 行程全文线性排版（含预算汇总，不含地图），2x 清晰度 | **微信群分享（主场景）** |
| JSON | 版本化完整数据 | 备份/迁移/分享导入 |
| PDF / 打印 | 打印友好排版 | 随身携带 |
| JSON 导入 | 校验后存为新行程 | 与导出成对 |

**验收**：长图在手机上直接可保存/转发；跨账号 JSON 导入 100% 还原为新记录；打印分页不截断活动；坏文件导入明确报错。

### F6 注册 / 登录 / 设置（v0.3 修订）

- **邀请码注册**：邮箱 + 密码 + 邀请码（站长在环境变量配置，可更换；无邀请码无法注册——保护站长的 Key 成本与小红书账号）。
- 登录以 httpOnly Cookie 会话保持；密码≥8 位、强哈希存储；未登录访问受保护页重定向。
- **设置页分级**：
  - 普通视图：仅显示昵称、账号信息、今日剩余配额——**无任何技术字段**。
  - 「高级选项」折叠区：BYOK（Base URL / API Key / 模型名 + 厂商预设）；配置后本账号生成走自己的 Key（不计站点成本，但仍计次数配额）；Key 服务端加密存储、仅回显尾 4 位。
- **Key 解析顺序**：用户 BYOK（已配置且启用）→ 站点 Key（环境变量）→ 均无则按 F1 异常表提示。

**验收**：

- [ ] 无邀请码/错误邀请码注册被拒；正确邀请码注册→登出→登录全流程可用。
- [ ] 普通用户设置页看不到任何技术字段；极客展开高级选项可配 BYOK 且生效。
- [ ] 库中密码与 Key 均非明文；Key 任何接口不回显明文；用户 A 不可访问用户 B 任何数据。

### F7 行程历史

- 「我的行程」列表：目的地/天数/活动数/总费用/数据来源标注/更新时间；操作：打开/重命名/删除（确认）/导出 JSON。
- 生成成功自动存为新行程；编辑更新原记录；上限 100 条/用户；按更新时间倒序。

**验收**：连续生成 2 次得 2 条独立记录；删除后不可访问；跨设备一致。

### F8 配额与用量（v0.3 新增）

- **用户配额**：每人每日生成次数上限（站长环境变量配置，默认 3 次；成功才计数）；表单页与设置页显示「今日剩余 N 次」；零点重置（服务器时区）。
- **全站小红书日额度**：MCP 调用（搜索+详情合计）全站每日上限（默认 500 次），用尽自动降级为模型知识调研（不阻断生成）。
- **用量记录**：每次生成落库（状态/token 消耗/是否用小红书），生成完成页显示本次 token 消耗；为站长后续核算成本留数据。

**验收**：

- [ ] 用满配额后第 4 次创建被拒、文案含重置时间；次日恢复。
- [ ] 失败/取消的任务不计入配额。
- [ ] BYOK 用户生成不消耗站点 Key（走自己的端点），但计入次数配额。

## 4. 关键用户流程

```
普通用户（微信里点开站长分享的链接）
  注册（邮箱+密码+邀请码）──▶ 我的行程（空态引导）
    └─▶ 新建行程表单（无任何技术字段）──▶ 三阶段生成（可取消/可离开再回）
          └─▶ 行程编辑器（清单+地图+预算）──▶ 自动保存 ──▶ 导出长图发群

极客用户：同上，可在 设置→高级选项 配置 BYOK
站长：VPS 上 docker compose up ──▶ 配置环境变量（站点 Key/邀请码/小红书 MCP）──▶ 分享链接
```

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 架构形态 | 前后端分离：React SPA → HTTP API（含 SSE）→ Agent 模型层；单机部署（Node + SQLite） |
| 部署 | 开源仓库提供 Docker Compose 一键部署 + `.env.example`；README 含站长部署指引（域名/HTTPS/小红书 MCP 登录） |
| 平台 | 现代桌面与移动浏览器；**微信内置浏览器为一等测试目标** |
| 响应式 | ≥768px 双栏；<768px 单栏三页签；核心流程以手机端体验为设计基准 |
| 持久化 | 全部业务数据存服务端 SQLite |
| 安全 | 密码强哈希；Key 加密存储不回显；httpOnly+SameSite Cookie；邀请码注册；登录/生成限流；**BYOK baseUrl 私网地址黑名单（多租户 SSRF 防护，站长可白名单豁免自有内网端点）**；用户数据严格隔离 |
| 合规（小红书） | **站长专用小号**（非主账号）单账号接入；严格只读；串行限速+缓存+任务级与全站日额度；笔记仅短摘要+署名链接，不整篇转存 |
| 性能 | 列表/详情 P95 < 300ms；SSE 推送延迟 < 1s；15 天×6 活动编辑无卡顿 |
| 开源 | MIT License；README（含截图与功能演示）；GitHub Actions（typecheck+build）；语义化版本 |
| 语言 | 界面简体中文（国际化列 V1.1） |

## 7. 成功标准

1. **非 IT 用户**从微信点开链接到看到第一份行程地图动线 **≤ 3 分钟**（注册 + 表单，全程无技术概念）。
2. 站长从克隆仓库到实例可用 **≤ 30 分钟**（含小红书 MCP 扫码）。
3. 小红书数据源生成的行程 ≥60% 活动可回溯来源笔记；行程无需手工修补即可导出使用。
4. 配额与邀请码机制使站长月度 LLM 成本可预估（用量数据可查）。
5. 全部验收标准（F1–F8 共 24 条）通过；`tsc --noEmit` 与生产构建零错误。
