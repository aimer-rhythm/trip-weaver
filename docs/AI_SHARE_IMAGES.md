# AI 行程分享图

详情页点击「分享行程」展开下拉菜单，选择「导出 PDF」或「AI 生成海报」。PDF 直接打开浏览器打印，在打印对话框里选「另存为 PDF」即可。AI 海报打开独立弹窗：选择旅行手账插画 / 水墨写意，点击「开始生成」，生成后可预览、下载、更换风格或重新生成；微信内可长按保存。JSON 备份入口已移除，导入格式不变。

选择、生成中和成品三个状态分别显示，生成中不显示下载或风格操作，使用无百分比的旋转 loading。生成成功后自动下载图片，不需要再点「下载」；每次显式生成（包括重新生成）成功均发起一次下载，并推送站内通知与完成提醒；仅回显已生成图片时不重复下载。生成任务挂在页面级 store 上：关闭弹窗、甚至退出详情页再进来，生成都会继续；再次点「分享行程 → AI 生成海报」会直接恢复生成中或已完成的界面（刷新页面同样直接回显服务端已保存的成品），不会自动弹窗。更换风格时保留已有成品，点击「返回已生成海报」可继续下载；重新生成失败也保留旧图。静态风格示例取自上海示例行程真实生成的成品图（`journal.png` / `ink.png`），与实际行程内容无关，最终海报使用接口返回的 1024×1536 图片。

`/share-styles/{journal,ink,painting-assistant}.png` 为产品素材：前两张是真实生图产出的上海示例海报，机器人为用户提供的透明背景高清原图；来源与提示词见任务中的 `research/assets-needed-2026-10-08.md`。用户提供的对比原图已不再用于选择卡。

按用户最终要求，预览、生成中和完成后三态统一使用 480×640px 窗口，小屏按视口缩小并保留 16px 外边距。切换状态不改变窗口位置或大小；内容区可滚动，标题、关闭按钮和底部操作保持可达。选择态保留「选择你喜欢的风格」标题，卡片保留缩略图、风格名与一行风格说明，主按钮全宽；成品图适应内容区高度自适应收缩，不出现滚动条。

## 配置

在服务端环境文件（本地 `apps/server/.env`，Docker 使用根目录 `.env`）填写：

```dotenv
IMAGE_API_BASE_URL=https://xjbh.lol/v1
IMAGE_MODEL=gpt-image2.5
IMAGE_API_KEY=在本地填写你的生图服务密钥

# 可选：第 2、3 个中转站，同样三件套加 _2 / _3 后缀（数量上限 3 个）
# IMAGE_API_BASE_URL_2=
# IMAGE_API_KEY_2=
# IMAGE_MODEL_2=
```

容器部署时 `data/media` 是只读挂载（景点封面由上游同步），因此 `docker-compose.yml` 单独把 `data/media/share-posters` 挂成可写目录；漏掉这条会导致生图成功但落盘失败。

重启服务后生效。密钥独立于 LLM、搜索和地图凭据，不会发送到浏览器，不自动复用其他 Key。未配置时生成按钮会显示明确错误。

书写顺序就是优先级。第一个站出现网络错误、超时、HTTP 5xx、429、鉴权失败、响应无图或图片过大时，自动换下一个站重试，用户无感知；HTTP 400 这类“请求本身有问题”的失败与本站地址配置不合法则直接报错，不做无意义的重试。缺少 `IMAGE_API_KEY_n` 的站点会被跳过，`IMAGE_MODEL_n` 留空则沿用 `IMAGE_MODEL`。序号必须连续（配了 `_2` 才读 `_3`），超出 3 个的配置会忽略并输出一条启动告警。

上述第三方地址和模型由用户指定；目前没有服务商文档，协议按 [OpenAI Images API](https://developers.openai.com/api/docs/guides/image-generation) 兼容实现，保留 `gpt-image2.5` 原样。该接口的真实模型可用性、尺寸支持和计费以服务商为准；项目验证使用模拟上游，没有消耗真实生图额度。

请求为 `POST {IMAGE_API_BASE_URL}/images/generations`，Bearer 鉴权，JSON 包含 `model`、`prompt`、`n:1`、`size:"1024x1536"`；兼容 `data[0].b64_json` 和 `data[0].url`。返回 URL 只允许安全 HTTPS 地址，服务器下载时不携带生图密钥、不跟随重定向。支持 PNG/JPEG/WebP，单张最多 10 MiB。降级链共享 180 秒总超时预算，每站使用剩余时间（最后一个可用站点可能只剩几秒）。反向代理超时需大于 180 秒，仓库的宿主机 Nginx 模板已设置为 1 小时。

## 提示词与体验

内置提示词位于 `apps/server/src/lib/tripSharePrompt.ts`，拆成「共用骨架 + 风格句」：骨架固定 1024×1536 竖版版式、内容约束与安全声明，风格句只有两句 —— `journal` 旅行手账插画（奶白底、湖蓝暖橙点缀、纸张质感）与 `ink` 水墨写意（宣纸米色底、墨色浓淡与飞白、青绿淡赭点染、朱红印章式点缀、大面积留白）。两种风格都提取目的地、标题、每天最多六个非住宿活动名称；长于七天的行程绘为摘要。不发送私人备注、住宿、日期、坐标、地址、活动描述和来源链接。图片包含“AI 创作 · 织程”角标；模型可能存在文字或细节偏差，水墨风格的中文长文本尤其容易出错，实际出行以详情页为准。

打开弹窗和选择风格不触发生图；用户点击生成才调用。进行中重复请求合并。成品持久化在服务端：图片按内容寻址落盘 `data/media/share-posters/<sha256>.<ext>`，索引写在 `trip_share_images` 表（主键 `trip_id + style`，同一行程同一风格只留最新一张，重新生成后删除旧文件）。打开弹窗时先 `GET /api/trips/:id/share-image?style=` 查已有成品，命中就直接回显 —— 刷新页面、重启服务都还在，不重复计费。行程内容改动后提示词随之变化，旧图不再回显（按「尚无成品」处理）。请求不携带 `style` 时按 `journal` 处理；可选 `regenerate: true` 仅在显式重新生成时传入，绕过已有成品，成功替换，失败保留旧图，进行中相同请求仍合并。切换风格再点击生成按新风格读取或生成，不会串图。同一站点失败不重试，配置多个中转站时按序降级，全部站点失败才报错并给出最后一次的真实原因。并发上限为每用户1个、全进程2个，HTTP接口另有6次/分钟限流。并发锁随进程重启丢失；图片存在本地磁盘，当前不支持跨实例共享或图片历史管理（只保留最新一张，行程删除后的孤儿文件暂不清理）。

## 检查

生成成功后，站内通知中心保存一条图片完成消息，同时弹出提醒并发起自动下载；关闭弹窗或切换站内页面仍有效。「重新生成」成功后会再次通知与下载；刷新页面回显旧图不会重复提醒或下载。通知中的「下载图片」获取对应风格的最新有效成品，原图被替换后也不引用过期链接。微信内显示长按保存引导。浏览器仅能确认发起下载，自动下载被限制时可使用手动入口；关闭整个网站后可在下次进入时从通知下载。

- 单元测试：`node --import tsx --test apps/server/src/__tests__/tripShareImage.test.ts`（需测试用 MASTER_KEY）；覆盖风格句替换、风格进缓存键、多中转站解析与降级。
- API：`node --import tsx scripts/verify-trip-share-image.mts`，临时 PostgreSQL 18797端口，自动建立并删除独立数据库。
- 浏览器：`node apps/web/tests/trip-share-image-browser.mjs`，模拟上游，检查显式生成、加载、失败重试、关闭重开、风格切换重新生成、下载、导出弹窗边界与手机布局。
- 示例缩略图：`node --import tsx scripts/generate-share-style-samples.mts`，真实调用两次生图接口产出 `apps/web/public/share-styles/{journal,ink}.png`；会产生费用，不要放进 CI。
- 服务端日志搜索 `[trip-share-image]` 查看成功/失败及耗时；不会输出提示词、返回图片或密钥。
