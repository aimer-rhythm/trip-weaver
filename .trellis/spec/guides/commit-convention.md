# Commit Convention

> **Purpose**: 让提交信息看一眼就知道改了什么、属于哪块工作，方便回滚、归档和事后追责。

---

## 三段式节奏

每个任务收尾按固定顺序落提交，不要交错：

1. **工作提交**（`feat` / `fix` / `refactor` / `docs`）——代码与规范改动，一次提交一件事。
2. **归档提交**（`chore(task):` / `chore(tasks):`）——`.trellis/tasks/` 目录移动与引用同步。
3. **日志提交**（`chore: 记录…`）——`.trellis/workspace/` 会话记录。

工作提交必须先落地，归档与日志在后。真实历史示例：

| Hash | Message |
|------|---------|
| `42b212b` | `feat(photos): 接入人工选图优先与后台视觉审核补图` |
| `fc97700` | `chore(tasks): 归档选图任务及五项已落地历史任务` |
| `48f25ee` | `chore: 记录选图验收与历史任务归档` |

---

## 格式

```
<type>(<scope>): <中文简述>
```

- 标题一律中文（2026-09 之后统一；更早的英文标题不再沿用）。
- 动宾短语，不加句号，控制在 20 字内。
- 正文可选：一到两句中文，说明做了什么 + 验证结果，例如 `42b212b` 的正文。

### type

| type | 用途 |
|------|------|
| `feat` | 新增能力或用户可见行为 |
| `fix` | 修 bug |
| `refactor` | 行为不变的结构调整 |
| `docs` | 规范文档、注释 |
| `style` | 纯格式 |
| `chore` | 归档、任务创建、日志、依赖维护 |

### scope

沿用已有词，不新造：`web`、`server`、`shared`、`photos`、`generation`、`routes`、`amap`、`export`、`ui`、`scripts`、`spec`、`task` / `tasks`。

---

## 规则

1. **简短优先**：写清动作和对象，不写“尝试”“初步”“可能”这类模糊词。
2. **一次提交一件事**：不混入其他任务的改动；无关的孤儿文件要么删掉，要么单独说明后再提交。
3. **未验收不提交**：用户未验收的工作保持任务 `in_progress`，改动留在工作区。
4. **归档提交要带量**：写成“归档选图任务及五项已落地历史任务”，让人看出归档范围。
5. **不 `--amend`，不 push**：除非用户当次明确要求。

---

## 检查清单

- [ ] 前缀与 scope 匹配改动性质
- [ ] 标题 ≤ 20 字、中文、无句号
- [ ] 没混入其他任务的改动
- [ ] 工作 → 归档 → 日志顺序正确
- [ ] 没有 amend、没有 push
