# 统一移动端顶部导航

## 目标
按用户要求移除首页移动端底部的「首页 / 我的行程」，统一使用其他页面已有的顶部导航栏切换。

## 要求
- 移除 AppLayout 在首页与行程列表上的底部导航及配套底部内容留白。
- 首页、行程列表与其他页面共用现有顶部胶囊导航，保留当前页高亮、通知、账号与生成进度入口。
- 两个导航入口统一位于顶部；访客点击「我的行程」沿用登录弹窗并保留首页草稿。
- 保留 guarded navigation、修饰键链接行为与桌面排版；320px 手机不溢出或重叠，点击区域至少 44px 高。

## 验收条件
- [ ] 移动端首页与行程列表不显示底部导航，不保留其底部占位。
- [ ] 顶部两入口可切换、当前页正确高亮；访客登录弹窗关闭后草稿仍在。
- [ ] 320 / 375 / 390px、平板、横屏与桌面布局通过回归。
- [ ] 类型检查、前端构建及现有相关浏览器回归通过，提供截图与本地预览。
- [ ] 等待用户明确验收；不提交、不归档、不运行自动收尾。

## 技术方案
移除 AppLayout 的 mobileTabs 路由分支，复用现有主导航；把原底部导航的访客点击处理保留在顶部链接中。更新现有 home-mobile-browser.mjs 的导航断言与前端规范。

## 范围
仅修改共用导航、相关回归与说明，不改首页规划表单、目的地地图或生成页面内容。保留工作区已有其他任务的改动。

## 决策
需求已明确；按用户「与其他页面一样」的要求复用现有顶部栏，无需增加新的导航方案或依赖。使用 inline 工作模式，不派发子代理。
