# 高德 POI 图片实测记录（2026-09-27）

## 1. 接口与图片可用性

```bash
curl -G "https://restapi.amap.com/v5/place/text" \
  --data-urlencode "keywords=西湖" --data-urlencode "region=杭州" \
  --data "show_fields=photos" --data "page_size=1" --data "key=$AMAP_KEY"
```

返回「杭州西湖风景名胜区」+ 3 张图：

```
https://store.is.autonavi.com/showpic/78e3e7b400e9290d0000003670488183
http://store.is.autonavi.com/showpic/d7a717ff724702f42595f6a3f09c6aba     ← http！
https://store.is.autonavi.com/showpic/4cf166ae69610bb30000006969158852?type=pic
```

**图片 URL 无 Referer 校验**，三种请求都是 `200 image/png`（309 KB）：

| 请求 | 结果 |
| --- | --- |
| 裸 curl（无 Referer、无 UA） | 200 image/png |
| `Referer: https://www.amap.com/` + 浏览器 UA | 200 image/png |
| 浏览器 UA，无 Referer | 200 image/png |

→ 可以直接热链。但 URL 是 http/https 混用的，**必须强制 https**，否则 https 页面会被 mixed content 拦掉。

图片有两个来源域，质量不同：

- `store.is.autonavi.com/showpic/...` —— 官方 POI 图
- `aos-comment.amap.com/...` —— **用户评论图**（2048×2048），河坊街与云栖竹径命中的就是这类

## 2. 覆盖率实测（20 个真实景点名，北京 10 + 杭州 10）

Pexels 与高德逐级串联（上游图库那级用杭州已有的 33 条 `payload.coverImage`，未参与本轮）：

| 来源 | 命中 | 景点 |
| --- | --- | --- |
| Pexels | 9 | 故宫、天坛、颐和园、北海公园、什刹海、国家体育场、西湖、灵隐寺、雷峰塔 |
| 高德补位 | 9 | 八达岭长城、南锣鼓巷、雍和宫、景山公园、九溪烟树、虎跑公园、河坊街、宋城、云栖竹径 |
| 仍无图 | 2 | 西溪湿地、龙井村 |

**合计 18/20（90%）**，对照只接 Pexels 时的 9/20（45%）。高德真实调用 11 次（9 命中 + 2 空）。

### 剩下两个的归因

```
西溪湿地 → 西溪国家湿地公园(3张) | 西溪湿地·洪园奇妙游(1张) | 杭州西溪湿地-水塘(0张)
龙井村   → 龙井村(公交站)(3张) | 龙井村路(0张) | 龙井村委会(1张)
```

- **西溪湿地是闸门误杀**：图就在第一条，但名字中间多了「国家」，归一后「西溪国家湿地」不以「西溪湿地」结尾 → 被拒。放宽需借助高德的 `type` 字段（「龙井村(公交站)」的 type 是公交站），否则会放进站点/路名。
- **龙井村该拒**：高德只有公交站、路名、村委会，没有实景图。闸门工作正常。

## 3. 配额与回写效果

配额分组（源自 `geocoder.ts` 的降级顺序注释，已实测踩过 10044 超限）：

| 接口 | 配额组 | 个人认证额度 |
| --- | --- | --- |
| `v5/place/text`（本适配器） | 基础搜索服务 | **5,000/月**（≈166/天） |
| `v3/geocode/geo`（地理编码） | 基础LBS服务 | 150,000/月 |

因此：单次生成 ≤3 次、进程内 24h 窗口 ≤40 次（≈1,200/月，占 23%）、命中后回写 `payload.amapPhoto`。

**回写实测**（本地 PG，3 个地点）：

```
第一轮：八达岭长城 → 高德命中 → 回写 ✓｜南锣鼓巷 ✓｜雍和宫 ✓｜高德调用 3 次
第二轮：三个地点全部直接命中库内回写｜高德调用 0 次
```

写回后同一地点终身零成本，这是把「每地点重复消耗配额」变成「一次性」的关键。
