# 行程专属旅行建议与注意事项

## 目标
在生成第三阶段调用 AI，结合最终行程、用户偏好、知识库证据撰写旅行建议和注意事项，取代总览中占主体的通用模板。

## 已确认需求
- 生成和重新规划时撰写并随行程快照保存；手动修改行程后标记待更新，不自动外呼。
- 建议必须关联实际入选地点与每日安排；知识库按最终活动检索，保留预约、避坑、分项政策和证据强弱。
- 标题继续与地理增强并发；专属建议在最终路线修复后写入，属于现有第三阶段，不新增用户阶段。
- 保留实时天气提醒；AI 不复述可能过期的天气预报。
- 旧行程和 AI 失败保留规则兜底；失败不能中断已完成的行程。取消仍中止，调用计入现有审计与 token 统计。
- 仅引用给定材料，不编造来源、票价、预约时间或官方政策；证据不足明确核实。

## 技术方案
- 新增可选 meta.advice 结构化快照，保存建议、注意事项、来源、生成时间与相关输入快照。
- 独立 submit_trip_advice 工具，校验活动 ID、证据 ID、条数与长度，来源链接由服务端回填。
- 最终行程按每批最多 8 个名称补充 SQL 检索；仅保留名称/明确别名匹配的结果，缺库降级为空材料。
- 前端匹配输入快照检测过期（忽略标题、照片、天气、保存时间与版本 ID）；过期内容不作为当前建议展示，显示更新提示和规则兜底。

## 验收标准
- [ ] 第三阶段实际调用 AI，结果经结构校验保存并在总览展示。
- [ ] 仅最终入选地点进入材料；跨天调整后的天序准确。
- [ ] 来源只能来自提供的知识库/候选材料，错误引用可重试；失败、取消、空知识库有覆盖。
- [ ] 手动改活动/日期/出行偏好后显示待更新；改标题、天气更新、另存版本不误报。
- [ ] 旧行程兼容，实时天气提醒保留，类型检查、相关测试和构建通过。
- [ ] 向用户提供验收结果后等待明确验收，不提交、不归档。
