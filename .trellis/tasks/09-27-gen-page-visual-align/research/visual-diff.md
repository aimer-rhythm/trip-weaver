## A. 生成页自身差异

### A1 标题天数取了 URL 兜底值，与真实任务不符（功能性 bug）

实测截图标题写「正在为你编织 北京 的 **3** 天旅程…」，而实际发起的是 `days: 4`。

根因：恢复链路打开的 URL 只有 `?city=北京`，没有 `start` / `end`，`NewTripPage.parseDraft()` 用
`isoDateAfter(1)` / `isoDateAfter(3)` 兜底算出 3 天，再作为 `days` prop 传给面板。
真实天数只存在后端 job 上，前端没有回填。

影响：从首页正常直达时 URL 带完整日期，标题正确；但**刷新 / 恢复 / 从编辑器跳回**都会显示错误天数。

### A2 标题装饰用的是 emoji

实现：`✈️ 正在为你编织 北京 的 N 天旅程… ✨ ✈️`（两个浮动的飞机 emoji + 星星 emoji）。
设计稿：标题两侧是四角星形光点与飘出的纸飞机剪影，且飞机在**背景层**（左上、右上各一只），不在标题行内。

### A3 候选拍立得从未渲染出照片（待确认）

60s 与 100s 两张截图里，右列始终是 3 张虚线空相框（`gen-polaroid-ghost`），没有照片、名称、`new` 贴纸。
对照上一任务 `09-27-planning-steps-glass/shot-03-gen-mid.png`，同样只有空框 + 一句「候选地点即将以明信片落位…」。

两种可能：候选事件确实还没到达（生成中位耗时约 195s，调研阶段占大头），或 `candidate` 事件在恢复链路里没被消费。
需要把截图窗口拉到 150~180s 才能区分。这是当前**唯一可能藏着真 bug**的项。

### A4 背景只有纯渐变，缺装饰元素

`apps/web/public/home-bg.png` 本身就是一张模糊的蓝粉渐变（实测确认），所以页面渲染出来的背景=渐变+光斑。
设计稿的背景在此基础上还有：两朵可辨认的云、两只纸飞机、右下角天坛剪影。这些在实现里完全不存在（无对应 CSS 元素）。

### A5 里程碑偏小偏灰，图标是 emoji

| 项 | 实现 | 设计稿 |
| --- | --- | --- |
| 图标 | emoji（🔍 / 🧭 / 📝），等待态叠 `grayscale(0.6)` | 线性图标（放大镜 / 指南针 / 文档），等待态为浅灰线稿 |
| badge | 56px 圆，2px 边框 | 同尺寸量级，但描边更细、有外发光 |
| 标题 | `1.05rem`（16.8px）粗体 | 约 22~24px |
| 副文案 | `0.82rem` 灰色；进行中用斜体呼吸 | 手写体风格、字号更大 |
| 关联线 | 2px 虚线，仅连接相邻 badge（`bottom: calc(50% + 28px)`） | 贯穿三点的细虚线路径 |

### A6 左右分栏比例

实现：`max-w-6xl`（1152px）居中，左列 `sm:w-[40%]`，右列 `flex-1`；两列间距 `sm:gap-10`。
设计稿：里程碑起点更靠页面左侧（约 12% 宽处），图标列与文字列间距更宽，整块内容视觉重心比实现更靠左、更疏朗。

### 第二轮再校准（09-27 晚）

叠图发现并修掉的：

1. **照片比例错了**：设计稿是略竖的拍立得（210×220 ≈ 1:1.05），实现原来是 4:3 横版 —— 这是卡片整体偏矮 60px 的主因。已改。
2. **卡片尺寸/白边**：宽 266 → 250，padding 12/12/6 → 20/20/16，caption 放大。
3. **卡片位姿**：`FAN` 前 5 个位姿改成按 UI 稿实测卡框换算的百分比（卡4 原来偏下 6%）。
4. **标题水平偏移**：设计稿的标题块整体比页面中心**偏右 36~40px**（实测文本中心 875.5 vs 页面中心 836，含两侧星形也是如此），已用 `margin-left: calc(80 * var(--ui))` 还原。

已落地：设计像素标尺 `--ui`、AppLayout 坐标补偿（顶栏 76px + `.app-main` 2.5%）、衬线字体（标题与里程碑标题用 `Noto Serif SC Variable`）、图钉形状 badge、右下角绿色勾徽章、彩色指南针、长虚线路径、A4 背景装饰已删。

### 无法靠 CSS 消除的剩余差异

1. **衬线字体的字身宽度不同**：位置、字号、总宽都对上了（文本中心 876 vs 875.5，总宽 756 vs 753），
   但叠图上从「北京」开始累积错位到「旅程」差 30px+ —— 设计稿字体的字距分布与思源宋体不同。
   同字号缩放到总宽相等时中间会对不上，只有拿到设计稿原字体文件才能 1:1。
2. **卡片数量**：设计稿画了 5 张，实现最多铺 6 张（`FAN` 有 6 个位姿），第 6 张在设计稿里没有对应位置。
3. 拍立得照片内容本身取决于图片源（高德 POI / Pexels 接入后已有真实照片）。
4. badge 的 3px 与按钮的 1~2px 属亚像素级累积误差，不再微调。

### 本次建的重测工具（都在本目录）

| 脚本 | 作用 |

| `measure-ui.mjs` | 扫设计稿像素：文本行带、绿/蓝 badge、照片区、文本列 |

> 踩坑：`chrome.kill()` 在 Windows 只杀父进程，且未关闭的 WebSocket 会挂住事件循环——
> 脚本末尾必须 `process.exit()`；实测曾累积 38 个 headless 残留把命令拖到超时。
> 另一个：`getBoundingClientRect` 返回的是**transform 后**的外接矩形，量旋转过的卡片（-8°）
> 会得到 295 而不是 265，要用 `offsetWidth`。
