# 换源调研：高德天气 → 和风天气

2026-10-04 用 tavily 读取和风官方文档（dev.qweather.com）核对，结论如下，未使用真实凭据联调。

## 为什么换

- 高德只覆盖当天 + 3 天且只有昼/夜两段，无逐小时：行程常跨 3 天以上，详情页大半是「预报待更新」。
- 和风逐日预报可到 30 天（v7 城市接口），中国境域 1km 分辨率，字段更全（最高/最低温、昼夜天气与风向风力、日出日落、湿度、紫外线）。
- 免费档每月 5 万次请求（之后 0.0007 元/次），本应用量级基本为 0 成本。

## 凭据与认证（决定 env 设计）

- API Host 是控制台分配的**开发者专属域名**（形如 `h2a9cf3mhs.xy.qweatherapi.com`），也是身份认证的一部分：只有凭据而不知道 Host 无法请求。
- 公共域名 `api/devapi/geoapi.qweather.com` **自 2026 年起逐步停服**，因此不做回落。
- 认证三选一，实现上 JWT 优先：
  - **JWT + Ed25519 私钥现签（采用）**：本地生成密钥对，公钥上传控制台，服务端用私钥签 `alg=EdDSA`、`kid`/`iss`/`sub`/`iat`/`exp` 的 JWT，走 `Authorization: Bearer`。**私钥不失效，不需要人工续 token**；实现里 15 分钟一签、提前 5 分钟自动重签。
  - 静态 JWT：已签好的 token 最长 24 小时，需人工重签，只当排查手段。
  - API Key：走 `X-QW-Api-Key` 头；和风自 **2027-01-01** 起限制 API KEY 的每日请求数。
- 结论：不再把 API Key 当主路径，配置项改成四项 `QWEATHER_JWT_*`。

## 接口选择

| 用途 | 接口 | 备注 |
| --- | --- | --- |
| 目的地 → LocationID | `GET /geo/v2/city/lookup?location=<名称>&number=2&lang=zh` | 返回 `location[]`，取首条 `id`/`name` |
| 逐日预报 | `GET /v7/weather/15d?location=<id>&lang=zh` | 只接受 `3d/7d/10d/15d/30d` |

- v7 城市逐日预报**已公告 2027-06-01 停服**，官方替代是 `/weather/v1/daily/{lat}/{lon}?days=N`，但那个上限只有 10 天。
- 权衡：15 天跨度只能用 v7。跨度常量集中在共享 `WEATHER_FORECAST_DAYS`，将来降到 10 天时改常量 + 路径档位即可。
- 响应 `code` 必须为 `'200'`；`updateTime` 是 ISO 带时区，归一化成中国时间 `YYYY-MM-DD HH:mm:ss` 以复用既有契约格式。

## 未采用的候选

- **Open-Meteo**：16 天、无需 Key、ECMWF/GFS 多模型，但中国区域是 9–11km 全球模型，且免费档仅限非商业用途。
- **心知天气**：免费档只有 3 天，15 天要 599 元/年起。
- **彩云天气**：强项是分钟级降水（2 小时逐分钟），日预报按量 7 天、专业版 10 天，长预报不是它的定位。

## 留下的坑

- 15 天里第 8 天起预报准确度急剧下降，产品上必须表述为趋势而非结论（前端已标「远期预报仅供参考」）。
- 2027 年有两个到期点：API KEY 每日限额（1/1）与 v7 接口停服（6/1）。spec `server/backend/trip-weather.md` 已记录。
- JWT 不是「一个可长期贴在配置里的串」：token 最长 24 小时，正确做法是存私钥、每次现签。这一点写成实现前最容易踩的坑。
