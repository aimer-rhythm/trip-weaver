# 接入高德出行天气并重设计详情总览

## 目标与需求

- 行程生成查询目的地和风天气；详情按每一天的真实出行日期匹配预报。
- 打开详情默认总览；切换天数、自动保存和对话修改后的定位保持原有语义。
- 重设计总览为每日路线、天气、出行建议与注意事项；去除“一路的风景”标题。用户已明确选择“出行手册”。
- 老行程进入详情可补查、刷新天气，无需重新生成，不因天气刷新产生行程版本。
- 和风覆盖当天起 15 天：日期未定、预报未覆盖、历史日期、服务失败分别诚实显示，不推算或编造天气；第 8 天起标注远期仅供参考。
- 天气使用站点级和风 API Host + API Key，遵守独立日额度与脱敏；天气失败不得阻断生成。
- 建议从真实预报、活动安排、预约信息和审核说明推导；没有天气不生成天气事实。

## 技术方案

使用可选 Trip.weather 保存生成时快照，独立 GET /api/trips/:id/weather 返回最新预报供 React Query 管理，避免污染编辑器自动保存与版本链。从上游 casts.date 精确匹配出行日期。服务端固定和风 API Host，城市解析与天气调用最多各一次并缓存、合并同请求；天气独立保守日预算。

**2026-10-04 换源**：由高德天气改为和风天气并彻底删除高德天气链路（`weather` 服务项、`AMAP_WEATHER_DAILY_BUDGET`、`integrations/amap/weather.ts`），不做供应商回落；跨度由 4 天提升到 15 天，凭据改为站点级 `QWEATHER_API_HOST` + 和风凭据（JWT 私钥现签优先，静态 JWT 与 API Key 降级）。

**2026-10-04 总览按参考图重排**：总览去掉重复的「目的地 · N 天旅程」抬头与副标题（只留「出行手册」）；每日卡片去掉 `01` 序号徽章，天气移到日期行右端，箭头换为 `forward`，路线行改用 `pin` 图标；「出行建议」改叫「旅行建议」，并与「注意事项」并排成纯圆点列表；删除总览底部「天气来源 + 更新天气」一栏，刷新只靠进入详情必查与 30 分钟自动刷新（因此 `/api/trips/:id/weather` 仍保留，但前端不再有手动入口）。

## 边界

不保留其他天气供应商回落、不做历史天气、不自动改路线、不定时后台推送；当前行程结构只有单一 destination，展示该目的地天气并标注城市。
