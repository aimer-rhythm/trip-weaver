# 优化详情页移动端标题栏

## 目标与要求
- 用户要求行程详情顶部标题栏适配手机，导出行程在手机上只显示图标，与历史版本操作协调。
- ≤600px 将返回、标题、历史与导出排成紧凑的一行，标题最多两行；日期、天数、人数在下一行自然排布，保留全文 title 和可访问名称。
- 历史、导出均采用现有 EditorIcon，44×44px 点击区域；手机隐藏文字，桌面保留文字。
- 沿用玻璃卡片、品牌色、已有导出菜单及历史弹窗逻辑。保留菜单层级、Escape/焦点、分享图/JSON/打印行为。
- 不改首页导航和前次待验收结果，不提交、不归档。

## 验收
- [ ] 320 / 390 / 430 / 600px、平板和桌面无横向溢出或按钮/标题遮挡。
- [ ] 手机图标按钮有可访问名称且可点击；长标题、日期与元信息可读。
- [ ] 导出菜单不被正文覆盖，分享图、JSON、打印和历史版本继续可用。
- [ ] 类型检查、构建、现有导出回归与截图完成，等待用户验收。

## 方案
复用 AppLayout 与 TripEditorPage 现有背景和样式；标题栏局部使用手机 grid 与 display:contents 整理同一套 DOM，避免复制标题与元信息。ExportMenu 复用 EditorIcon export 并隐藏手机文字。更新既有 trip-share-image-browser.mjs 的可访问定位与屏幕尺寸断言。

## 范围与依据
已读前端组件规范、目录规范、质量规范和 Trellis before-dev/check/update-spec，采用 inline 模式。保留其他任务工作区改动；上一导航任务仍待用户验收。
