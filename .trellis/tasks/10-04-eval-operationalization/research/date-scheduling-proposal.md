# 日期排程调整方案

2026-10-05 用户已授权实施；本方案已实现，结果见 [实施与验证](implementation-followup.md)。下文保留方案提出时的问题与范围；当前等待用户验收。

## 问题与真实证据

96 次真实生成中，两个北京备注场景在 2026-10-19（周一）安排了携带「周一闭馆」字段的故宫博物院：

- `beijing-notes-avoid-remote`：不去两处长城和环球影城，只在市区活动。
- `beijing-notes-food-no-spicy`：北京本地美食、不能吃辣、不安排购物。

原始产物：`eval/runs/campaign-2026-10-05-live-matrix/beijing-notes/2026-10-04T17-41-51-237Z-232ffa73`。失败来自最终保存行程，不是模型只在文本中建议了闭馆地点。

避开远郊场景的实际分组如下；括号指产物中的营业字段，不宣称已独立核实真实开放政策。

| 日期 | 景点 |
| --- | --- |
| 周一 | 故宫（周一闭馆）、景山、什刹海、南锣鼓巷 |
| 周二 | 天坛（周一闭馆）、雍和宫、奥林匹克公园、颐和园 |
| 周三 | 鼓楼、北海、国家博物馆（周一闭馆）、杨梅竹斜街 |

`apps/server/src/generation/scheduling/schedule.ts` 先按路线成链、容量切段，再对整段做日期匹配。三段均有周一闭馆点，因此任意交换整段，周一都会留下一个闭馆点。当前“最少冲突”分支仍保存该点；它不具备段内地点跨日重新组合能力。

此问题与已实施的餐厅按日期过滤不同。不能通过删除故宫、丢弃整天、放宽闭馆检查或随机重跑挑一份绿报告来证明修复。

## 建议实现

保持原有整段匹配作为快速路径，仅在匹配结果仍有部分闭馆冲突时触发有界修复：

1. 建立入选景点的日期可用性矩阵，复用 `isClosedOnDate`。未知营业时间保持未知；不据此捏造开放保证。
2. 先尝试将闭馆点移到有剩余容量的开放日，再尝试跨日点交换。存在故宫→景山等先后关系时，应考虑关联的最小组合；不可修闭馆却破坏已承诺的游览顺序。
3. 对每个候选方案重算受影响日期的重量/数量上限、独占日、先后约束与段内顺序。强独占点仍独占，不为了闭馆修复制造长城与市区混排。
4. 有界搜索采用稳定的比较顺序：先减少闭馆冲突，再尽量保留入选点，再降低跨区绕行，最后减少改动。设明确搜索上限和稳定平局规则，避免随候选数量爆炸或不确定性。
5. 景点日期确定后，按实际日期重新选择午晚餐；不直接把旧餐厅带到新日期。后续重算受影响的交通连接，并检查活动 ID、邻接顺序、`legs` 与保存结果一致。
6. 所有候选修复均失败时，不把冲突方案伪装成可执行成功。返回结构化的未解决冲突及原因，通过现有生成失败/提示路径告知用户改日期或调整要求；不静默删必去景点。具体用户文案与 API 结果在实现时按现有错误契约接入。

可供搜索验证的重组示例：将周三的「鼓楼、北海」与周一的「故宫、景山」作为两组交换。这样周一变为鼓楼/北海/什刹海/南锣鼓巷，周三包含故宫/景山/国家博物馆/杨梅竹斜街，12 个景点均保留。**这只是候选方案示意，尚未通过容量、真实路线或可行性验证，不能直接交付为新行程。**

## 影响范围与实施边界

- 主要影响 `generation/scheduling/schedule.ts`、相关顺序/容量辅助函数与 `buildDraft.ts` 的冲突输出；必要时接入现有 orchestrator 失败提示。
- 更新排程回归测试、真实失败 fixture 回放及 backend generation spec。
- 不改知识库营业事实，不覆盖旧行程，不重写已完成的 96 例报告，不新增预算评估。
- 长通勤在本轮已有独立观测。此修复至少不能新增明显路线退化；全面重做距离/偏好目标函数另行定范围，不把它隐含为本方案的一部分。

## 验证与验收条件

1. 两份北京原失败数据用相同候选、相同日期和偏好做确定性回放，闭馆冲突消失、必去/避开语义不回退；输出前后地点和分天对照，解释未排入项。
2. 覆盖单点移动、双点交换、先后组合、不同星期闭馆、假日例外、1 日无解、15 日上界、无日期、无坐标、远郊独占和美食餐次。
3. 所有修复结果重新检查每天容量、顺序、实际日期营业、交通邻接、唯一 ID、持久化与 SSE 终态；无解时必须可识别，不能以空天/删点掩盖。
4. 对原 96 份候选及可用排程输入做离线回归，明确哪些输入需要补采；最终 Trip 的旧快照重评分不能替代重跑当前排程。
5. 固定同一知识版本，真实重跑两个失败场景及北京 3/5 日各偏好；再跑 `eval:flow` 与 typecheck。旧 FAIL 保留，新结果单列，不能称旧基线已全绿。
