# 详情对话处理过程展示与新增行程天数

状态：根据用户追加需求继续实施；本轮完成后重新交付验收，验收前不提交、不归档。

## 用户需求

- 增加详情对话中「思考过程」的显示内容。
- 对话修改行程支持新增行程天数。
- 普通问答接入关键词与向量混合 RAG，支持按需联网搜索；新增日期复用生成调研和排程流程。
- 修复最新回答的后续建议缺失：仅最新完成回答显示 2～3 条基于本轮回答的建议；新一轮处理中隐藏旧建议，不在每条历史回答下同时展示。

## 实施范围

- 展示来自真实处理阶段的进度与简短说明，保留到对应回答以供回看。
- 支持「再加一天」「延长两天」等修改，在现有行程后追加日期与活动，并同步总天数、日期、版本和对话锚点。
- 复用现有修订流程、真实候选和历史版本机制；失败不修改原行程。
- 现有工作区包含其他任务未提交修改，只增量调整相关实现。
- 普通问答使用当前问题、行程地点及偏好构造检索条件，向量与关键词均参与融合，缺配置/失败时保留 SQL 结果。
- 最新政策、营业/预约/交通等时效问题、明确联网请求或本地证据不足时使用现有网页来源；回复持久化可点参考资料。
- 新增日期复用 research tools/prompt、候选证据与确定性排程；按新增起始日期检查闭馆，排除已有活动，保留原日期内容。
- 查询有取消、超时与调用预算；失败不虚构已联网或已核验，追加调研/排程失败不落不完整新版本。

## 默认决定与待确认偏好

- 用户已确认：处理时展开，完成后折叠，可随时手动展开查看。
- 新增天数默认追加到末尾，既有日期和活动尽量保留；遵守现有产品天数上限。
- 展示面向用户的处理摘要，不包含内部提示词、原始模型推理或技术调试日志。

## 验收条件

- [ ] 处理过程有多条可理解的真实阶段记录，回答完成和重新进入对话后可回看。
- [ ] 对话可将已有行程延长一天或多天，新日期含可用行程安排。
- [ ] 天数、结束日期、版本列表和当前编辑器保持一致，原版本可恢复。
- [ ] 无效天数、服务失败和并发/过期修改保护有效。
- [ ] typecheck、构建、定向回归与浏览器检查通过。
- [ ] 普通问答和美食检索确实调用向量融合；向量不可用仍保留关键词检索资料。
- [ ] 按需网页搜索、来源显示与刷新持久化可验证，外部资料视为数据而非指令。
- [ ] 新增日期实际调用共用调研与排程，保留来源/简介、排除旧活动、日期正确且旧行程不变。

## 范围外

- 全站重设计、全量生成流程改版、历史版本删除。
- 用户未验收本轮修改前不执行提交、归档或完成标记。
