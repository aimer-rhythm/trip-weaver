# 顶部导航与后台生成通知设计

## 状态

方案初稿待评审；用户要求先出方案。本轮只记录设计与调研，不进入产品实现、提交或归档。

## 目标

将全局导航简化为首页、我的行程，以及按状态出现的生成入口；用户可在生成期间浏览其他页面，返回原进度，完成后从通知直达行程详情。

## 用户已明确的需求

- 删除顶部导航的个人资料、设置入口。
- 添加明确的首页、我的行程按钮。
- 导航品牌只显示 Logo，删除中英文品牌名；桌面与手机一致。
- 通知与退出均使用图标；通知有未读时仅在图标右上角显示小红点，不展示计数，点击展开通知面板。
- 生成期间可以离开进度页，并从导航重新打开。
- 生成完成后通知用户，点击通知进入行程详情页。
- 先交付方案设计。

## 已确认的范围

2026-10-05 用户选择：**仅站内提醒：浏览其他页面时提示，重新打开网站可查看未读消息**。

不请求浏览器通知权限，不做系统推送、邮件或短信。关闭网站期间任务仍由服务端执行，完成消息写入账号，用户下次进入网站时可见。

2026-10-05 补充确认：全端品牌仅 Logo，通知仅铃铛图标与未读小红点，退出仅图标。原方案的品牌文字、通知计数与桌面退出文字均取消。

2026-10-05 出图要求：UI 提示词必须基于当前产品功能、布局与文案。首页保留中国地图与四段规划胶囊，我的行程保留搜索／筛选／排序与书脊封面，生成页保留三阶段小径与扇形拍立得，详情保留对话／行程／地图。方案中的新增生成卡片暂不作为出图必选项，不将建议功能描述为已有功能。见 [UI 出图提示词](ui-prompts.md)。

## 导航方案

沿用浅色蓝紫品牌、磨砂白胶囊与轻阴影，重新整理信息层级。

桌面示意（方括号为可点击入口）：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  [Logo]  [首页] [我的行程]     [杭州 · 生成中 ↗]  [铃铛图标·]  [退出图标]  │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 左侧仅保留现有品牌 Logo，点击回首页；不显示「织程」或「TripWeaver」文字。链接提供可访问名称「返回首页」。首页与我的行程成为常驻一级导航。
- 当前导航采用淡蓝底、蓝色文字、明确选中状态。首页精准匹配；行程列表与详情归入我的行程；生成页由生成状态入口标明当前位置。
- 个人资料、设置入口删除，不重新藏入账户菜单。旅行偏好继续在首页调整。
- 额度说明移到首页「生成行程」操作附近，避免导航持续拥挤。
- 桌面和手机的退出均使用同一套线性退出图标，不显示文字；与通知保持间距，桌面悬停或键盘聚焦时提示「退出登录」，并提供同名可访问名称。
- 右侧通知常驻为铃铛图标，桌面和手机均不显示「通知」文字。有未读时仅在图标右上角显示小红点，不展示数量或 99+；无未读时隐藏红点，仍可点击查看历史。
- 点击铃铛展开通知面板，再次点击、点击外部或按 Escape 收起。打开面板不会自动清除未读；全部通知已读时红点才消失。
- 铃铛提供「通知，有未读消息」／「通知，无未读消息」的可访问名称与展开状态，避免只用颜色传达未读状态。示意图中的「·」表示右上角小红点，不是文字字符。
- 有当前任务时显示「杭州 · 生成中」，点击直接回到该任务的进度页，不多打开一级面板。生成结束后入口收起，未读通知仍保留。
- 状态入口只显示真实任务状态与目的地；具体阶段、耗时放进度页，不使用模拟百分比。

### 手机布局

```text
┌────────────────────────────────────┐
│ [Logo] [首页] [我的行程] [铃铛图标·] [退出图标] │
│ [进度图标 杭州  生成中     查看进度 →]  │
└────────────────────────────────────┘
```

- 与桌面统一使用纯 Logo、铃铛和退出图标；首页与我的行程保留文字，图标按钮均有可访问名称。
- 任务入口移到导航下方的第二行，仅有任务时出现；不把全部项目挤进同一行。
- 桌面通知为约 360px 下拉面板；手机为底部抽屉，支持关闭、Escape、焦点返回。
- 点击热区至少 44×44px，支持键盘、可见焦点和减少动态效果设置。
- 导航保持可达；生成状态不能仅以颜色或动画表达。详情页可用高度包含第二行导航，避免遮挡地图和列表。

## 生成、返回与通知流程

1. 用户从首页开始生成。提交动作由全局管理，按钮立即给出「正在提交」反馈；服务端接收后展示任务与进度。
2. 生成页增加说明：「你可以先去看看其他行程，生成完成后会在站内通知你。」主导航始终可用。
3. 点击首页、我的行程或其他站内链接后，服务端继续工作，顶部持续显示当前生成入口。
4. 点击顶部入口，进入独立且可刷新恢复的进度地址（拟 `/generations/:jobId`）；恢复同一任务、真实阶段与耗时，不重新发起生成。
5. 我的行程顶部增加轻量的「正在生成」卡片，显示目的地、天数、阶段与「查看进度」，与导航读取同一状态。
6. 生成结束按当前页面分流：

| 用户所在位置 | 成功时表现 |
| --- | --- |
| 当前任务的生成页，页面可见 | 保留现有自动进入详情行为；成功打开后该条通知标记已读，不重复弹提醒 |
| 首页、我的行程、其他行程详情 | 保留当前页面，右上角弹出完成提醒，并显示铃铛右上角的未读小红点 |
| 浏览器标签页在后台 | 保存未读；回到网站后更新状态并给出合并提示，不在后台强制切换站内页面 |
| 网站已关闭，后续重新打开 | 从账号读取未读通知；不重放一串历史弹窗，不自动跳详情 |

7. 成功后我的行程列表刷新；临时生成卡片移除，正式行程卡片显示在列表中。已有筛选条件继续有效。

完成提醒文案：

```text
杭州 3 天行程已生成
路线与每日安排已准备好。
                         [查看行程]  [关闭]
```

- 整条提醒及「查看行程」均能进入对应详情；关闭按钮只关闭提醒。
- 建议停留 8 秒，鼠标悬停或键盘焦点进入时暂停消失。关闭提醒不会把消息标记已读。
- 提醒消失后仍可从通知面板或我的行程打开。

## 通知面板

```text
通知                            [全部已读]
────────────────────────────────────────
● 杭州 3 天行程已生成
  刚刚                         查看行程 →

  北京 4 天行程已生成
  昨天 18:32                   查看行程 →
```

- 内容包含状态图标、目的地与天数或行程名、发生时间、操作入口；未读点与字重共同区分状态。
- 打开面板不自动全部已读。点击成功通知并成功打开对应详情后标记该条已读；也可主动全部已读。
- 已读状态按账号保存，同账号再次登录或新标签页可同步。
- 空状态：「暂无通知，行程生成完成后会出现在这里。」
- 加载失败显示重试；不能将请求失败误显示为没有消息。
- 分页读取历史；不回填上线前所有旧生成记录为新通知。
- 失败、超时采用低干扰站内消息：「杭州行程暂未生成成功」，提供回首页检查并重试的入口；不自动再生成。
- 主动取消展示操作结果，不额外推一条失败通知。
- 行程已删除或失去访问权限时，显示「该行程已不可用」，提供返回我的行程，不落入空白详情页。

## 关键边界

- **同账号一个进行中任务**：沿用服务端限制。此时首页生成操作改为「查看正在生成的行程」，避免用户误以为可以同时提交第二份；首页其他选项仍可浏览调整。
- **离开不是取消**：保留独立的取消生成操作，切页、关闭通知与断开 SSE 均不能调用取消接口。
- **切换行程前保存**：从正在编辑的详情点击首页、我的行程、生成入口或通知时，统一等待当前修改保存；失败留在当前页并可重试，不能静默丢失修改。待完成的路线规划也必须纳入离开判定，不能仅假定 flush 成功即全部安全。
- **网络中断**：显示「连接恢复中」，不能把暂时断网当成生成失败；重连后按快照与事件补齐。
- **任务过期**：进度链接先查任务，终态内存已过期时用持久化结果解析到详情或失败说明。
- **服务重启**：当前生成执行仍是单实例内存任务，服务器重启不承诺断点续算；显示任务不可恢复并提供重试。已保存的结果与通知不受内存过期影响。
- **幂等**：同一任务的完成消息只存一次；SSE 重放、刷新及前后台切换不重复弹。多标签页协调可见标签展示，已读从服务端同步。
- **账号隔离**：退出时清理连接和缓存，切换账号不显示上一账号的任务或消息；所有查询、标记已读均校验归属。
- **偏好快照**：用户离开生成页后可能修改首页偏好。完成旧任务不能把新草稿误存为旧任务偏好，也不能用旧成功回调覆盖新草稿；完成保存应基于发起时的选择快照，与现有首页账号记忆任务协调。
- **删除设置入口后的文案**：所有「去设置填写 Key」等引导同步调整，避免指向不存在的入口。已有个人配置数据不在此次导航改版中清除；如后续需要管理自有 Key，另行设计入口。

## 技术设计建议

### 前端

- 在登录后的 AppLayout 上挂载单一 GenerationProvider（概念名），统一管理发起／接管、恢复、SSE、终态、导航状态。
- 现有 useGenerationRun 改为共享状态的消费接口，生成页卸载不销毁全局任务监听。
- 提交链路（建会话、写 Brief、启动任务）也需防止页面卸载使任务被遗留；用户离开后迟到回调不得拉回生成页。
- 路由分开新建入口与具体任务进度，打开现有任务不经过 autostart 分支。
- 服务端通知与是否存在未读消息由 React Query 管理，导航只消费 hasUnread，不展示计数；URL 标明 jobId／tripId，不把编辑器 Zustand 用作任务或消息缓存。
- SSE 继续提供精细进度；收到终态时刷新通知、列表和额度。恢复网站／焦点／网络时补查任务与未读状态。
- 提议先用可见页面每 15 秒的轻量通知检查覆盖其他标签发起的任务；当前已知任务通过 SSE 即时更新。隐藏页面暂停轮询，重新可见立即同步，避免新增第二套流连接。
- 通知面板与 Toast 共用一套目标解析和离开保存流程。

### 服务端

- 新增当前用户进行中任务查询（拟 `GET /api/generations/current`），解决关闭重开、新标签页、sessionStorage 丢失后的发现问题；补充目的地、天数、阶段摘要。
- 新增账号通知表（概念字段：id、userId、jobId、type、tripId、title、message、createdAt、readAt），按 userId + jobId + type 唯一约束去重，按用户与时间索引。
- 成功通知与行程、成功审计在同一个数据库事务内写入；提交成功后才发送 job_done。保证任何终态提醒都指向已经保存的结果，网页不在线也有通知。
- 通知加载与标记已读接口支持单条、当前已知消息集合的全部已读和分页；“全部已读”使用时间／游标边界，不能误读操作期间新到消息。
- 失败和超时通知在释放运行锁后尽力写入；数据库故障需可观测，不能让通知故障把任务永久卡住。主动取消不创建通知。
- jobId 终态解析可从新通知记录找到 tripId，不依赖 30 分钟内存快照。旧任务保留兼容行为，不批量制造新消息。
- 现有 generations 是配额事实来源，id 为独立审计 ID，不能直接假设它等于 jobId；不改动现有扣额规则。

## 取舍记录

| 方案 | 评价 |
| --- | --- |
| 仅把生成监听移到全局，消息保存在浏览器 | 改动小，但网页关闭期间的完成消息不能可靠保存，不满足重新打开查看未读 |
| 全局生成状态 + 账号持久化通知 | 推荐；满足站内切换、重新打开网站与未读同步，复用现有生成服务 |
| 系统 Web Push | 用户已明确本次仅站内，排除 |

## 后续实施顺序

1. 任务发现与账号通知持久化、接口、幂等及归属测试。
2. 全局生成生命周期、独立进度路由、当前编辑保存与偏好快照协调。

## 验收标准

- [ ] 首页／我的行程在主要页面稳定可达，个人资料与设置入口已删除，选中态准确。
- [ ] 桌面和手机导航均仅显示品牌 Logo，无中英文品牌名；通知与退出仅用图标，具备提示与可访问名称。
- [ ] 通知有未读时只在铃铛右上角显示小红点，不显示计数；点击可展开面板，全部已读后红点消失。
- [ ] 生成 A 后离开到首页／列表／行程 B，A 持续运行；从顶部入口恢复 A，不新建任务、不重复扣额。
- [ ] 手机有清晰的生成入口，375px 等窄屏无横向溢出、不遮挡编辑器。
- [ ] 在 A 的生成页等待时，成功后自动打开 A；在其他页面收到通知时保持当前位置。
- [ ] 点击通知正确打开 A，且 B 的待保存修改不会丢失；保存失败保留 B。
- [ ] 关闭网页后 A 完成，再打开网站可见账号未读；终态超过 30 分钟后仍可打开对应详情。
- [ ] 关闭 Toast 不消除未读；点击并成功打开详情或主动标记已读后，状态刷新／重新登录仍一致。
- [ ] SSE 重放、断线恢复及多标签不会产生重复持久消息或重复扣额。
- [ ] 失败、超时、取消、缺失任务、删除行程和账号切换均有清晰处理。
- [ ] 首页偏好在任务完成期间不会因旧回调覆盖新的用户修改。
- [ ] 通知落库与行程提交的成功边界有集成测试；请求归属与幂等有测试。
- [ ] 实现后通过相关测试、typecheck、web build、桌面／手机交互验证，并由用户明确验收。
