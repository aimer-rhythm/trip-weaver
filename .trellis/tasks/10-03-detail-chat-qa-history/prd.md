# 详情页问答交互与手动编辑历史修复

状态：实施中，完成实现和自测后交付用户验收；验收前不提交、不归档、不标记完成。

## 用户需求

- 详情对话采用问答交互，一次只问一个问题，提供 2～3 个可点击回答建议，避免表单填写。
- 起始「推荐美食 / 看看沿途玩法 / 检查行程节奏」跟在初始化回答后，仅作为起始建议；后续建议属于各条回答，不常驻输入框底部。
- 手动修改行程也保存为历史版本，可查看和恢复，原历史版本保持不变。
- 参照 `C:/Users/Aimer/Downloads/历史版本.png`（图 1）和 `C:/Users/Aimer/Downloads/生成初始化.png`（图 2）校对历史版本与初始化对话 UI。

## 已知与决定

- 在现有未提交的详情对话/历史功能上增量修改，不回退其他任务工作。
- 用户已补充展开历史面板的切图：右侧窄白色抽屉、纵向时间轴、白色版本卡、绿色正在查看标记、底部说明；桌面保留背景遮罩与外侧留白，窄屏使用全屏面板。初始化文案与三条建议跟随图 2，聊天主要文字继续保持已确认的 16px。
- 手动编辑沿用防抖自动保存；每批实际保存产生一个新版本，无变化不建版本。保存进行中的新编辑继续排队，不覆盖草稿；失败重试幂等。
- 新版本同步 URL、版本缓存与会话锚点，保留当前日期、阅读位置及输入草稿。
- 推荐卡的位置调整改为逐步问答选择，沿用原有真实候选、冲突校验和一次添加规则。
- 只读历史、跨用户、过期请求、保存失败及恢复竞争继续保护。

## 验收条件

- [ ] 初始化文案与三条建议在对话流中，输入区没有常驻建议。
- [ ] 每条追问有 2～3 个上下文回答选项，点击形成用户回答；后续建议随回答保留。
- [ ] 推荐卡调整日期、餐次、位置没有多字段表单，逐步选择可取消或修改。
- [ ] 拖动、移动、删除、添加及标题等手动修改产生可恢复版本；刷新仍存在。
- [ ] 迟到保存回执不丢草稿；重复重试不重复建版本；历史写入被拒绝。
- [ ] 历史列表最新/正在查看标记、空态、加载失败、预览和恢复清晰，桌面/窄屏不溢出。
- [ ] typecheck、生产构建、定向版本/对话回归及浏览器验证通过，提供验收预览。

## 实施与验证

复用 `detailChatService` 的对话理解/真实正文流，持久化追问选项。保存复用版本链与事务幂等；前端保存回执仅更新身份和时间戳，保留未提交编辑。沿用项目 token、Button、Modal。

范围不包括全站重设计、逐字段差异视图、历史删除和全量生成调整。原先被覆盖且未存入历史的内容无法追溯补回。

本轮实现、自测与验收截图见 [实施记录](research/implementation.md)。验收条件的勾选保留给用户确认。
