# 系统 UI 一致性与通用交互组件统一

## 目标

检查全站按钮、弹窗、下拉选择、输入框、文本域及操作菜单，沿用现有蓝色圆角视觉体系，统一外观与键盘、加载、禁用、错误反馈，消除页面复制样式。详情页移除编辑活动及查看完整详情的展示入口。

## 范围

- 公共 Button / IconButton（共享按钮基础与变体）、Input / Select / Textarea、Modal、确认与输入弹窗、操作菜单。
- 覆盖首页、登录、行程列表、详情、设置、聊天输入、导出和地图控件；日历与路线选择保留领域语义，复用基础交互。
- 替换浏览器原生 confirm / prompt；统一弹窗命名、焦点返回、Escape、遮罩与窄屏滚动。
- 用户已确认全部移除：活动卡片的编辑和查看详情菜单、对应详情弹窗、两种地图点位的编辑入口；保留概要、排序、跨天移动、删除与添加活动。
- 正常路线查询不显示重试按钮，失败重试保留 loading。

## 实施选择

在现有 React 19 + Tailwind 4 上建立小型通用组件，不引入新 UI 库。原生 select 保留操作系统选择体验，外观和焦点状态统一。组件显式 variant，页面只负责布局和业务状态；不使用运行时解析 className 猜变体。

## 验收

- [x] 常用交互控件统一引用公共组件，常规按钮样式不再复制。
- [x] 全站操作菜单支持 Escape、焦点离开和点外部关闭。
- [x] 弹窗标题可访问、焦点可恢复、内容在移动端可滚动。
- [x] 详情活动编辑/完整详情入口按确认范围移除。
- [x] typecheck / build 及首页、设置、列表、详情、路线浏览器回归通过。

## 风险与边界

不改变路线、生成、保存和导出业务协议，不重新设计品牌或页面结构。地图 SDK 内 HTML 字符串使用共享静态样式，不伪装 React 组件。特殊地图标记、日历网格、分段选择允许专用布局，但共用焦点和禁用反馈。
