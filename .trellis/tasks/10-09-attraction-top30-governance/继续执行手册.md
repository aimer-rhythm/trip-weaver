## 每轮阅读的固定流程（已脚本化）

```powershell
cd .trellis/tasks/10-09-attraction-top30-governance/research
# 1) 抽取（含已读复用，节省体积）
python -X utf8 -B extract-entity-readthrough.py 西安 <完整主名1> <主名2> ... `
  --reuse-notes-from seven-cities-semantic-readthrough-<上一条>.json > "$env:TEMP\<city>-r<n>.txt"
# 2) 用 read 工具分块读取该文件（每块 ≤50KB / ≤170 行）
# 3) 写 cases-*.json（见 cases-xian-a/b/c.json 模板），再运行通用固化脚本
python -X utf8 -B record-readthrough.py cases-<批次>.json
# 4) 重绘名单与台账（换新的 ledger 编号，脚本不会覆盖历史台账）
python -X utf8 -B refresh-seven-review.py --readthrough seven-cities-semantic-readthrough-<新>.json `
  --ledger seven-cities-review-ledger-<新>.json
```

要点：

- `record-readthrough.py` 自动装配 mention/noteEvidence/哈希，只校验 cases 里的 `mentions`/`notes` 计数与每条 `quotes` 是否逐字出现在 `note_desc` 中（断言失败即中止且不写入）；`[已读复用]` 的 note 只保留前 160 字符，引文必须落在该前缀内，且 ` ⏎ ` 只是抽取脚本对换行的显示替换，引文里不要带它。
- 计数断言（`expectedFromItems` / `expectedToItems` / `expectedToMentions`）必须严格递增。
- `refresh-seven-review.py` 会重写 `七城人工审核名单.md` 与 `七城剩余问题.md`，并保留 `## batch-120完整验证` 之后的人工追加段落。
- 环境：系统 python（`python`）可跑纯 JSON 脚本；涉及 sqlalchemy/dotenv 的脚本用 `D:\Project\xhs-travel-pipeline\.venv\Scripts\python.exe`。
