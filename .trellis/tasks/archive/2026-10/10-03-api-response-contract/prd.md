# 统一 API 响应契约与前端请求处理

## 已授权范围
用户同意统一请求层、登录失效处理和错误契约，并明确要求响应为 `{ code, message, data }`。

## 契约与实现
- 所有 `/api` JSON 响应统一外层，成功 `code=0`、`message=成功`，业务值位于 `data`。失败保持 HTTP 4xx/5xx，已有业务字符串码优先，否则使用 HTTP 状态码；附加错误字段放入 `data`，无附加信息为 null。
- HTTP 201/202 等状态、Cookie、限流头保留。SSE 帧、OAuth 重定向、静态文件与无实体响应遵循原协议；SSE 建连前的 JSON 错误使用统一外层。
- 服务端集中在序列化边界包装，保留现有响应 schema 对业务数据的过滤，避免散落手写外层及重复包装。
- 前端 fetch 统一请求头、凭据、JSON 解包、错误分类、默认超时和可选取消；SSE 共享建连与 HTTP 错误处理，长流保留自己的超时策略。
- 统一接管业务请求 401，清理用户缓存并跳转登录，保留原路径；登录错误不重定向、不循环。4xx 不盲目重试，网络/5xx 的查询有限重试，写操作不自动重试。
- 业务特定错误继续由业务视图呈现，不增加重复的全局 toast。
- 现有资源 URL 与合法业务动作保持稳定，本次规范响应与传输层；不因 REST 名称改造任务取消等动作。
- 同步现有脚本、模拟响应和文档中的契约消费者。
