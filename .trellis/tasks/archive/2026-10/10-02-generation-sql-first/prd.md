# 优化行程调研召回与模型调用耗时

> 2026-10-02 用户明确要求「提交并归档本次任务」，已授权验收后的收尾。最终提交、隔离验证与限制见 [research/closeout-record.md](research/closeout-record.md)；下文各轮「等待验收」描述保留为历史过程。

## 目标与授权

用户在代码与只读检索分析后明确要求「按照这个方式进行优化」。采用结构化 SQL 批量召回为主、向量按需补充、模型筛选与撰写简介；减少标题阶段模型往返。无需再次确认方案。实现自测后交付验收，用户验收前不提交、不归档、不标记完成。

## 要求

- 改进已验证地点召回：别名、类别、推荐分、主景点归并和空间多样性；固定参数化 SQL，不采用模型生成 SQL。
- 生成开始时按城市、天数、节奏、偏好预取候选和证据，直接提供给调研模型；仅不足时补查。
- 关键词结果足够时不调用向量；自然语言偏好或覆盖不足仍保留按需向量。在线 embedding 使用短超时、可取消、缓存，不继承离线回填重试/节流。
- 候选采用稳定地点引用，复用检索证据和坐标，避免已检索地点重复查库；保留现有新增候选与外部来源降级。
- 标题一次正常工具调用提交并结束；保留字体覆盖检查、有限重试与默认标题降级。
- 修正耗时脚本的重叠阶段计时和模型响应耗时口径，提供可复现的对比。
- 保持地点 city/verified 限制、证据强度、来源、取消、额度、终态和持久化契约。

## 验收条件

- [x] 北京多主题候选不会全部被天坛入口/机位占满，杭州无 themes 仍可形成有效候选。
- [x] 明确地点足量命中时零 embedding 请求，语义补查仍有效；超时与取消不拖长生成。
- [x] 已预取候选可直接写入，无须模型先搜索；常规标题一次提交结束。
- [x] 排程、未覆盖城市、字体失败、取消和隔离数据库生成回归通过。
- [x] 类型检查、相关测试、计时对比及规范更新完成；用户已授权提交归档。

## 范围边界

不更换用户模型/供应商，不改前端交互。第三轮用户明确要求路线不走回头路，范围扩展为确定性段内顺序优化；选点容量、分天、闭馆与远郊独占契约保留。第四轮用户明确授权上游及当前知识库修复；先备份，再归一旧数据并生成独立行程验证，不覆盖用户已有行程。

## 第二轮：按真实生成样本继续优化（2026-10-02）

用户测试「北京古都三日经典游」后要求继续优化。首个请求到保存 208.418 秒，其中首轮请求到第二轮 179.208 秒；首轮输出 17,835 tokens（全程 19,247），13 个候选均使用已预取 placeId。该时间不包含初始化，不能当作精确点击到完成时间。

- 增加一次 `submit_research(candidates: [{placeId, intro}], summary?)` 完成已知地点选择与提交；复用现有入池与逐条 SSE，保持外部地点的 `add_candidate` 降级。
- 批次先验证城市、verified、类别、引用与容量，错误不部分写入；去重、取消、官方预约、来源与照片规则不变。
- 已知地点名称、类别、预约与来源由代码复用；提示不再重复传递来源 URL，不要求模型规划日期/路线或写长摘要。
- 仅在生成阶段为明确识别的 DeepSeek V4 原生模型 ID 显式发送 `thinking: {type: 'disabled'}`，通过 SDK 请求体测试验证。未知模型和对话入口保持现有配置，不降低输出上限以免截断工具调用。
- 使用隔离数据库与模拟模型验证一轮调研、事实完整性及取消；真实网关是否采纳关闭思考参数、总耗时和输出质量需后续实测，不将模拟耗时当提速证据。

## 第三轮：内容质量与避免折返

- 预约状态与说明先做一致性校验：冲突、仅名称或含混政策降为 unknown 并提示核实；官方种子仍优先，已知和外部候选共用校验，不回写知识库。
- 简介只写地点定位与看点；第三轮的生成端删句方案已由第四轮上游提纯方案取代。来源链接保留，预约说明独立展示。
- 日内有界搜索可行顺序，先减少明显回折再缩短路程，不增加原有几何路程；出入口先后、未知坐标、餐次、已排时间等约束不能为求顺路而破坏。
- 初次排程及坐标补齐后都可排序，地理腿按最终邻接关系计算；用北京真实生成快照回放，并新生成一份行程验证回折清除、地点不丢失。
- 保留生成提速，不增加模型审稿轮次；隔离库回归和真实样本离线回放后交付验收，不提交归档。

## 第五轮：上游完整介绍作业入口

### 用户后续纠正：介绍由搜索与模型知识共同获取

- 完整介绍以搜索得到的景区官网、政府文旅等正文构建事实骨架，模型自身知识补充稳定背景、解释与导览组织；小红书只补充体验、避坑等其他信息。
- 上游介绍作业不再依赖小红书摘录长度或笔记存在。默认主动搜索并抓正文，搜索摘要不直接当证据。
- 网页事实句保存真实引文/URL；模型知识句单独标注，不能伪造引文，具体数字、年代及政策仍需来源。网页/模型知识两类信息均进入预览，原已复核内容保持。
- 搜索结果按城市/地点/模型缓存7天，单点最多抓3页；支持取消和逐点搜索失败结果。Web/CLI/脚本使用相同默认搜索模型，不修改全局搜索配置。
- 以下第五轮原始实现中的「仅用已采集资料」已被此修订替代。机器提纯与用户验收仍严格区分。

- Web 新增「完整介绍提纯补充」，按当前城市、可选规范名/别名、单次1～200个补缺；默认20个，可只预览。
- Web/CLI 一键全链路默认在聚合分级后调用共用提纯，可关闭；不增加自动全量采集或隐式导出。
- 已有完整及编辑复核内容一律保留；仅同城有效、坐标已解析的规范主景点参与。缺资料不编造，机器提纯不标成编辑复核。
- 正文逐句保留原文及出处，确定性校验后机器审稿；逐条写入前备份并比较当前快照，取消保留已完成结果。
- Web 结果展示正文、来源、跳过/缺资料/未通过/并发冲突，复用现有任务、进度、取消框架。
- 验证上游测试、前端构建、实际 Web API 小范围预览；不重跑全城采集，不提交归档，等待用户验收。

- 撤回生成端按关键词删整句；已提纯的介绍/看点优先复用，动态政策与看点分开，保留来源与原文限定。
