# 行程展示页设计方案与 gpt-image 提示词

## 方案

已确认：按天旅行手册 + 紧凑图文卡片。

布局默认：顶部延续全站胶囊导航；下方紧凑行程工具栏；主体左侧对话 22%、中间行程 46%、右侧地图 32%（扣除间距后的比例）。对话和地图保留原功能；中间内部滚动，天数导航吸顶。

中间：全程概览 / 第一天 / 第二天 / 第三天 / 第四天，默认第一天；每日主题和日期 → 按游览顺序排列的图文活动卡 → 相邻地点交通信息。卡片默认显示顺序号、名称、短安排、重要预约提醒、小照片及右上角更多图标。卡片不显示「详情」「编辑」按钮，不设底部操作栏。更多菜单收纳查看完整信息、编辑、上移/下移、跨天移动和删除；完整介绍和来源从菜单进入。新增活动、增删天、跨天移动、备选清单及已有保存/版本/导出入口保留。

视觉：蓝青淡紫柔和背景、深蓝文字、宋体页面主标题、生成页同款手写每日主题、磨砂胶囊、浅白阅读面板、白边照片。活动卡片增加双层蓝灰柔和阴影，呈现轻微浮起的立体感。导出、发送按钮沿用首页可用态的品牌蓝渐变与白色文字；助手消息不显示头像或头像占位。正常正文使用清晰无衬线字体。避免照片重叠、旋转和大面积装饰占用阅读空间。

状态：旧行程缺少照片或调研内容时仍正常阅读；空日给添加入口；保留无坐标、估算交通、预约提醒、保存失败信息。无对话的行程使用中间/地图两栏。小屏切换分区，不强塞三栏。

## 可直接复制的提示词

请为中文 AI 旅行规划产品「织程 TripWeaver」设计一张高保真桌面网页 UI 效果图，横向 16:9 构图，以 1920x1080 的逻辑画布安排界面。输出正视、平面的完整产品界面，文字与控件清晰，具有真实可落地的网页布局。

设计主题是「按天阅读的旅行手册」。这是已生成行程的查看和编辑页面。参考附图中的首页与生成中页面，延续浅蓝、青色、淡紫交融的柔和背景、深海军蓝文字、白色半透明磨砂胶囊、轻盈阴影、宋体标题和白边照片质感。主体阅读区域使用接近不透明的浅白色，确保内容清楚。背景色彩主要从页面边缘与栏间透出。

【整体布局】
顶部保留一条横向磨砂玻璃圆角胶囊导航，左侧品牌「织程 TripWeaver」，右侧「我的行程」「设置」等低调导航。
下方是高度紧凑的行程工具栏，左侧返回按钮、标题「北京 · 四日漫游」，副信息「10月16日—10月19日 · 4天 · 2人」；右侧安排「导出」。标题使用端正规整的中文宋体，工具文字使用清晰无衬线字体。
工具栏下方为三个并列区域，扣除间距后宽度比例严格接近左22%、中46%、右32%。边距约24px，栏间距约16px。中间行程栏明显最宽。三个区域高度一致，圆角约20px，细白边和柔和阴影，视觉协调但不层层堆叠厚重容器。

【左侧：对话区】
展示两三条自然简短的中文对话，示例用户「第一天想轻松一点」，助手「可以，把主要游览集中在中轴线附近。」助手消息不显示头像，不使用机器人、人物或品牌图标代替头像，也不预留头像占位栏；消息从左侧内容边缘开始。用户消息右对齐。消息气泡简洁，留白舒适。底部固定圆角输入框「说说你想怎样调整行程…」和首页同款品牌蓝渐变发送按钮。它是已有对话功能的视觉呈现，不增加预算、预订、推荐商品等新功能。

【中间：按天旅行手册，设计重点】
顶部是一排精致的胶囊页签：「总览」「第1天」「第2天」「第3天」「第4天」，第1天以首页同款品牌蓝选中，白色文字。附近提供次要入口「备选清单」。页签下方显示每日手写主题「沿着中轴线，走进老北京」，使用生成页同款「千图笔锋手写体」（QianTuBiFeng Handwriting），深蓝色、约24—28px，有自然笔锋且清晰易读；小字「10月16日 · 第1天」使用无衬线体。总览中的每日主题也沿用这款手写体。页头紧凑，避免大幅封面。
活动卡片采用接近不透明的浅白底、约16px圆角、细白边与清晰可见的双层蓝灰柔和阴影：近处小范围接触阴影，叠加向下扩散的大范围环境阴影，参考 `0 3px 8px rgba(35,65,115,.07), 0 12px 28px rgba(35,65,115,.12)`。卡片静止时就能看出轻微浮起的立体感，不依赖悬停。中栏内边距约20px，为阴影留出空间，避免被裁切；照片阴影比卡片更轻。避免硬黑投影、厚重外框和浮雕效果。
正文使用按当天游览顺序排列的紧凑图文活动卡片列表。卡片左上角用小巧的「01」「02」「03」标识顺序。卡片占满中间阅读区的可用宽度，不留独立时间栏，不绘制时间轴、圆点连线或日历时段格。所有卡片文字为主，卡片采用两行布局：第一行是小序号、地点名称，第二行左侧为类别、两行简短介绍及必要预约提醒，右侧放约112—136px宽、4:3比例的小照片。照片使用白色细相框和轻柔阴影，水平端正，不倾斜、不重叠。卡片内边距约16px，标题行与图文之间留8—12px，图文间距约16px，卡片高度约150—170px，长标题或必要提醒可自然撑高。更多图标不覆盖照片，其触达区域至少44×44px。卡片没有底部操作区，不保留按钮删除后的空白。
第一张完整卡片：顺序「01」，地点「故宫博物院」，类别「文化古迹」，两行短文「从午门开启今日漫游，感受宫殿建筑与中轴秩序。」；直接可见的浅琥珀预约提醒「需提前预约」；右侧为故宫真实摄影感照片。卡片底部不显示任何操作按钮。
两张卡片之间显示独立、轻量的相邻地点交通信息：「步行约15分钟 · 估算」，与卡片文字左边缘对齐，用小型交通图标和一行文字表达，不放进巨大卡片，不绘制竖向连接线，最右端是常驻的水平三点更多图标。
第二张完整卡片：顺序「02」，地点「景山公园」，类别「公园」，短文「登上万春亭，俯瞰故宫与北京中轴线。」；右侧小幅景山绿树与亭阁摄影。沿用相同的右上角更多图标，不添加预约提醒，也不为缺少提醒留出空行。
下方露出第三张卡片的开头：顺序「03」，地点「北海公园」，显示部分湖面与白塔照片，自然暗示内容向下滚动。中间区域有细而低调的滚动条。以排版清楚为优先，不为容纳全部行程而缩小文字。
正文14—16px，地点标题18—20px，每日手写主题24—28px。名称、顺序与提醒具有清晰层级，按钮触达空间充足。手写体集中用于每日主题与总览中的每日主题；页面主标题保留宋体，景点名称、对话、正文、日期、交通、预约提醒与按钮使用清晰无衬线体，避免全页手写化。

【按钮与主题色】
直接沿用首页「开始规划」按钮可点击状态的视觉作为页面主题：从左上浅品牌蓝 `#5b8cfb` 到右下品牌蓝 `#2f6bf3` 的渐变、白色文字或图标、圆润轮廓和柔和蓝色投影，投影参考 `0 12px 26px rgba(47,107,243,.35)`，按按钮尺寸适度缩放。导出按钮使用圆角胶囊，发送按钮使用紧凑圆形，均采用这套颜色与材质。选中天数、地图当前天筛选沿用品牌蓝；次要控件使用浅蓝底与蓝色图标，不将所有操作都做成强主按钮。灰蓝 `#c3cfe8` / `#aebddc` 仅用于禁用态，不作为正常主按钮颜色。地图路线的不同日色和预约提醒的琥珀色保持语义区分。

【右侧：地图区】
展示清晰的北京城区二维道路地图，浅色底图、公园绿色、水系浅蓝色；标有故宫、景山等位置。使用与现有产品一致的彩色路线、编号地点标记。顶部保留「全部」「D1」「D2」「D3」「D4」筛选，D1处于选中态，其余天路线淡化。右下角显示放大、缩小控件。地图占满自己的容器，保持实际地图的空间感与信息密度，不改成插画或立体沙盘。

【整体质量要求】
这是精致、轻盈、可阅读的旅行产品工作界面。中间行程是第一视觉重点，地图和对话清晰可用。背景柔和，内容对比充分，图标使用统一细线风格。中文文案尽量准确，布局边界和文字基线对齐。
不要设备外壳、透视模型、宣传海报、大面积标题装饰、飞机云朵插画、重叠拍立得、emoji图标、深色主题、密集后台表格、无意义图表、酒店预订价格或额外功能区。不要把生成中的进度步骤带入已完成行程页面。活动卡片上不要出现「详情」「编辑」文字按钮、底部操作栏或悬浮在照片上的操作图标。当前产品没有时间轴概念，不显示09:00等活动时刻，不显示空时刻占位，不推算到达时间，不使用上午/下午分段，不自动添加餐次。交通分钟数只表达相邻地点的路程耗时。
不要给助手消息添加任何头像或空白头像栏，不要把每日主题全部换回宋体，不要把活动卡片画成缺少阴影的扁平白块，不要给主按钮另设紫色、黑色或灰蓝色主题。
只输出一张完整的设计效果图。
