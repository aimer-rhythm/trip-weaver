# 现有 UI 与重构方向（方案草案，未确认）

## 最新修订：提高密度

以 PRD 和 design-prompt.md 最新版本为准：1920×1080 首屏目标至少4张完整卡片，第5张按剩余空间展示；取消独立跨卡标题行，左文字、右112×84照片、最右44px更多操作位并排，卡片约112–128px高，交通行约28px。工具栏右端仅导出。地图右下角包含放大、缩小、默认视图（四角取景框，恢复当前筛选路线视野）。地图已有自动适配视野逻辑，但独立按钮属于本轮追加要求。版本与行程信息入口去向暂不擅自决定。

- global.css：对话 300px、行程 430px、地图占余宽。宽屏的新增空间主要落在地图，中间信息仍较拥挤。
- DaySection：天主题编辑、折叠、删除、添加活动；住宿首尾交通及相邻活动交通，估算标记。
- ActivityCard：保留旧时间字段的渲染（缺失时显示 `--:--`）、地点、类别、描述、匹配景点的照片/简介/预约/来源、坐标状态；上移下移、跨天移动、编辑、删除。旧组件的时间字段不能作为当前产品存在时间轴的依据。
- 产品约定：`09-22-plan-no-timeline-chain-split/prd.md` 已明确去时间轴、只算景点间通勤；`generation/scheduling/schedule.ts` 也明确活动位置只表达阅读顺序。此次用户再次确认无时间轴。
- MapView：全部/按天筛选与中栏共享 dayFilter；非选中天在地图淡化；地图点可进入编辑；渲染器及降级机制需保留。
- 手机现有对话/行程/地图页签。新布局需照顾 1024–1280 宽度，不能机械缩放三栏。

## 推荐 A：按天旅行手册

- 桌面三栏按可用内容宽度约 22/46/32，左栏最低约 280px；约 1440 宽度时 300/620/430px 随实际边距调整。
- 中间顶部紧凑行程摘要，下方「总览 / D1 / D2 …」吸顶导航；默认 D1，总览显示每天主题和路线摘要。
- 单日标题、日期、活动数量；交通数据完整时可给交通时长汇总，否则明确不完整，不能伪造精确值。
- 按当天游览顺序排列活动卡，用卡片内小序号表达顺序，整合安排与景点内容，避免两份介绍默认重复展示；默认地点、短介绍、照片及必须预约提示，详情展开查看完整内容与来源。无时刻列、圆点时间轴或推算时刻。
- 相邻地点交通信息显示在两张卡片之间，保留估算提示；不自动补住宿路段或餐次，不按交通时长推算活动时间。
- 按用户最新要求，卡片仅保留右上角更多图标，完整信息、编辑、上移/下移/跨天/删除收进菜单，保留键盘可操作方式。取消底部操作栏，首行序号与标题、右端更多；下方左文字右照片。添加活动置于当日末尾，添加天/删除天/备选有明确入口。
- 沿用 dayFilter 同步机制，保留地图原筛选与点编辑行为；不新增自动定位或 AI 修改协议。
- 无会话时两栏约 60/40。窄屏切换页签；具体断点方案后续确认。

## 替代方向

- B：全程连续游记。一次读完全部天，旅行叙事强；长行程滚动较多，可配天数锚点。
- C：跨天日程板。每一天一列，便于比较/调整分配；三栏框架下中间过窄，易引入横向滚动。

## 边界

现有手动编辑、自动保存、版本、导出应保留；仅重组入口不删除能力。无图片、无 overview 的旧行程、长地名、多天、空日、无坐标和保存失败均需有明确展示。暂不扩展预算、预订、分享或新增生成能力。
