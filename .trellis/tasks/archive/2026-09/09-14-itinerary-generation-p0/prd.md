# 行程生成 P0：坐标复用、定位地名与局部修订

## Goal

在保留调研、编排、审校、地理合理性与可行性检查的前提下，减少已有调研地点的重复定位、展示文案造成的无效查询，以及修订阶段不必要的整程重建。

用户于 2026-09-14 明确要求「从 P0 开始处理」，沿用本会话已评估的三项 P0，不再重复请求范围确认。

## Requirements

1. 调研坐标与行政区划码通过任务内索引复用到活动地理解析；不把原始 POI 数据加入公开 Trip/候选 schema。
2. 区分活动展示名和定位地名，优先显式定位信息；兼容旧工具调用，对规范餐次名称提取片区，不将菜系或整段文案当地点搜索。
3. 复用只接受可识别、无歧义的真实来源结果，仍走既有坐标合理性校验；未命中时沿用现有定位链、限流、额度和如实降级。
4. 定位信息变更时使旧坐标与相关路线失效；仅修改时间、描述等内容时保留已解析地点信息。
5. 首次规划和修订使用独立指令与工具能力；修订禁止重建骨架，提供当前草稿，允许保留活动 ID 的跨天移动和局部修改。
6. 保留最终路线重算、餐次检查、最终可行性报告、取消与 SSE 行为。

## Acceptance Criteria

- [x] 已调研且可唯一匹配的活动复用坐标/adcode，测试中不发重复地点定位请求。
- [x] 未命中、同名歧义、非法/异地坐标仍按安全的原有定位或降级路径处理。
- [x] 餐次展示名称不变，但定位仅使用实际片区或显式地点。
- [x] 地点变更清除陈旧数据；时间/描述编辑保留坐标和未变化路线。
- [x] 修订工具集合不包含 set_trip_skeleton，跨天移动保留活动 ID，当前草稿随修订请求提供。
- [x] 新增内部定位引用不泄漏到持久化 Trip JSON，旧调用与旧快照兼容。
- [x] 针对性回归测试、完整 server 单测、typecheck、必要的 mock C2 集成与离线评测通过。
- [x] 记录可复现的外呼次数差异；不把 mock 或旧快照通过宣称为线上提速/质量保证。

## Technical Approach

- 复用现有 ResearchOutcome、DraftTrip、GeoSession、TypeBox Agent tools 和质量检查。
- 任务内保存地点引用和定位名；公共 Trip schema、数据库结构保持兼容。
- 用生成路径的 mock 外部服务/工具验证真实调用次数与输出，而非仅匹配实现字符串。
- 按当前 Trellis inline 流程由主会话实施和检查，不分派子 Agent。

## Decision

采用三项已批准的 P0 修正。坐标复用必须经过现有地理校验；修改阶段能力收窄，避免提示词冲突。后续需要对话编辑时可继续复用该局部修改机制。

## Out of Scope

- 更换 Agent 框架、模型、提供商或数据库。
- 调整 QPS、超时、调用额度、熔断阈值、共享缓存策略。
- 删除审校阶段或降低质量门槛。
- 对话 UI、服务端行程版本控制、生产部署与推送。
- 重建在线评测金集或调用真实付费提供商；当前验证使用隔离的 mock 与离线数据。
