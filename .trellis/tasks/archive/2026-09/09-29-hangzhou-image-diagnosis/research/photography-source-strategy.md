# 从“能配图”转向“展示风景摄影”的图源建议

2026-09-30。根据用户提出的摄影品质目标进行代码核对与8次真实Pexels查询；本次为选型研究，不等于用户已批准新的生产排序。

## 结论

建议建立精选景点图片库：国内具体景点用摄影用途的小红书采集及摄影师/景区授权作品补充，Pexels作为便于接入的摄影图库来源。所有来源先过景点身份校验，再按画面质量与展示适配排序。无法确认地点的城市主题图只用于城市封面，不给具体景点卡片冒名配图。

只更换关键词会继续被“高收藏、多图攻略”的过滤机制影响；仅把Pexels提到最前也无法保证地理准确和审美一致。

## 当前代码事实

- `app/web/keywords.py` 的关键词目标涵盖攻略、住宿、美食、避坑、打卡，未分离摄影采集。
- `app/crawl/filter.py` 以最低收藏数、最低图片数过滤，再按收藏×2+点赞+分享×1.5排序。这衡量笔记实用热度，不是摄影质量，并可能丢掉低收藏的单张佳作。
- `app/vision/classify.py` 的CLIP分辨风景、人物、拼图等内容类型；`rank_scenery` 按该分类分数排序。scenery置信度不能当作构图、光线与成片质量分。
- `researchTools.ts` 本地图命中即停止后续Pexels查询；因此图库里即使有更好的照片也没有比较机会。
- Pexels现有适配器查询中文地点名、最多取15项，然后返回第一个文本匹配项；没有跨候选的摄影质量排名，主要取medium尺寸，也没有持久保存摄影师等完整作品信息。

## 真实小样检索

8个查询：杭州西湖/West Lake Hangzhou、灵隐寺/Lingyin Temple Hangzhou、西溪湿地/Xixi Wetland Hangzhou、飞来峰/Feilai Feng Hangzhou。
参数为 locale=zh-CN、orientation=landscape、size=large、per_page=8。原始结果：`pexels-query-comparison.json`；总结果数不能当准确覆盖率。

| 查询 | 观察到的前列结果 |
|---|---|
| 杭州西湖 | 多条描述明确为杭州西湖、传统建筑和游船，可进入候选复核 |
| 灵隐寺 | 既有杭州寺庙建筑，也有没有具体寺名的通用寺庙照片 |
| 西溪湿地 | 第一条描述为越南潘切，第二条为西班牙维拉法菲拉；不能作为西溪照片 |
| 飞来峰 | 包括越南山景、哈萨克斯坦雪山等无关图 |
| 对应英文查询 | 更偏向杭州，但“西溪”和“飞来峰”前列出现相同候选；英文名不能替代身份复核 |

这些是检索相关性观察，尚未完成8组照片的逐张审美打分，不能称Pexels全面优于现有图片。

## 建议改造

1. 增加摄影用途的采集任务，保留原攻略任务。新关键词示例：杭州西湖风光摄影、苏堤晨雾摄影、三潭印月日出摄影、灵隐寺建筑摄影、九溪秋色摄影、西溪湿地秋色摄影。减少旅行攻略、保姆级、打卡模板类词。
2. 摄影任务允许1张优质实拍，不按最低收藏数硬拒绝；用场景/作者信息扩展候选，再在图片层过滤攻略拼图、主角人像、明显水印遮挡、模糊和过曝。
3. Pexels同时尝试中文、英文地名与确定别名，按用途取横/竖图；保留来源ID、作品页、摄影师、使用条件和适配尺寸。官方curated接口不能按某个地点筛选，不能直接当景点精选接口。
4. 将地点正确性设为门槛；门槛内再比较主体清晰、光线层次、构图、游客遮挡、色彩自然、清晰度和卡片裁切。VLM/审美模型作为排序辅助，用人工选片样本校准。
5. 为景点维护3—5张精选候选，选定封面后稳定复用；有新作品进入才重新评选。不要每次生成随机取搜索第一张，也不要按来源固定先到先得。
6. 原图尺寸、横竖比与页面展示一起处理；光有“专业原图”，若只取小尺寸并裁掉主体仍然无法达到目标。

建议先做杭州10个核心景点样板，每个收集少量跨来源候选、精选3—5张，再依据真实的准确覆盖率、视觉偏好和使用条件决定扩大哪个来源。

## 图源使用条件

Pexels官方API文档允许按orientation/size/color/locale搜索，要求显著链接回Pexels，并要求尽可能署名摄影师；详情以官方文档为准。小红书公开可访问不等于得到在产品中展示摄影作品的授权；面向公开产品应记录授权依据或选用许可适合的图库。

官方证据：https://www.pexels.com/api/documentation/

复现命令：

```powershell
smart-search fetch https://www.pexels.com/api/documentation/ --format json
node --env-file=apps/server/.env --import tsx .trellis/tasks/09-29-hangzhou-image-diagnosis/research/compare-pexels-queries.mjs
```

工具边界：smart-search doctor发现主搜索模型不可用，使用同一CLI中可用的Tavily网页读取能力；Pexels官方文档读取成功。Pexels帮助中心特定页面及Unsplash文档本次读取为空，未以它们支持条款结论，也未调整全局搜索配置。
