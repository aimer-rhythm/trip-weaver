# 对话建议仅显示并关联最新回答

## 目标

按用户要求，详情页对话建议只在最新一轮回答下显示，且内容必须承接该回答，避免历史建议堆叠或重复出现无关的固定选项。

## 要求与边界

- 没有详情对话且没有待处理回答时，欢迎区保留起始建议。
- 只有消息列表末尾的助手回答可以显示后续建议；旧回答的建议不显示。
- 新一轮回答生成、停止或失败但仍有待处理消息时，不显示旧建议。
- 最新回答没有建议时，不回退到旧回答的建议。
- 保留历史消息、餐厅卡片和问答澄清选项的现有行为。
- 后续建议根据本轮问题、完整回答、真实候选和当前行程生成 0～3 条具体追问，保存于该助手消息附件；不再套用固定菜单。
- 按钮展示短标题，点击发送包含具体主题/地点/日期的完整问题，继续保持只读咨询行为与原日期范围。
- 澄清问题不额外生成建议；生成建议失败或没有合适内容时留空，不影响已经生成的正文。
- 兼容旧附件数据，但历史固定枚举建议不再作为后续建议显示；空对话仍有起始菜单。
- 添加餐厅的确定性回复使用关联餐厅/日期/餐次的建议，不额外调用模型。
- 修正对话输入框选中时的双重高亮：内嵌 textarea 不出现蓝色直角 outline，外层保持圆角焦点环；保留发送按钮键盘焦点、多行和手机布局。

## 验收标准

- [x] 空对话显示起始建议；已有对话不再显示起始建议。
- [x] 多轮对话仅最新回答下显示建议，历史回答正文仍显示。
- [x] 新一轮进行中不显示旧建议，完成后显示新回答的建议。
- [x] 最新用户消息、无建议回答、停止或失败的待处理消息不回显旧建议。
- [x] 新回答包含具体追问；点击发送该回答附带的问题；刷新后仍绑定同一回答。
- [x] 模型异常/非法建议留空，旧数据仍可读取，建议点击不能触发行程编辑。
- [x] 输入框鼠标/键盘聚焦没有内层直角框，外层圆角提示清晰，多行与手机布局正常。
- [x] 类型检查、前端构建及相关验证通过，交付用户验收后再提交或归档。

## 实现与验证

在 `ChatPanel` 保留最新消息显示限制；共享 suggestions 扩展为兼容旧枚举的结构化建议（label/text/kind）。服务端完成正文后通过已有 runner 的只读结构化工具生成建议，最多等待 8 秒；与答案一起持久化。测试覆盖共享校验、模拟模型输入/输出和客户端 SSE。使用 trellis-before-dev / trellis-check / trellis-update-spec 执行实现与复核。
